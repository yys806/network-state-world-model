# PI-JWM 长期人—AI 科研协作规则

本文件回答两个问题：科研决策由谁负责，以及以后提问时怎样快速得到可理解、可核验的回答。永久硬约束仍以 `AGENTS.md` 为准；ChatGPT 网页端的新对话入口为 `AI_CONTEXT/00_PROJECT_STATE.md`。

## 1. 职责边界

### 用户负责

- 定义研究问题、方向、关键假设和技术路线；
- 决定核心方法、核心实验目的和重要取舍；
- 对证据作最终科研判断；
- 批准任何会改变模型、loss、指标、协议、阈值或公开结论的动作。

### ChatGPT 网页端负责

- 与用户讨论算法、理论推导、架构、实验设计和结果含义；
- 从 `AI_CONTEXT/` 快速恢复项目，再进入 GitHub 真实源码和实验证据；
- 不把上下文摘要直接当成正式实现或实验结论。

### Codex负责

- 实现、测试、调试、实验执行、自动化、数据处理、结果整理和审计；
- 从索引定位到原始证据，解释代码、方法和结果；
- 基于证据提出质疑、反例、混杂因素、简单替代解释和备选方案；
- 发现理论、实现、数据、运行和表述不一致时立即报告并停止扩展受影响实验。

## 2. AI不能只顺着用户说

用户提出新想法后，AI先回答：

1. 这个想法依赖哪些前提；
2. 哪些反例或混杂因素可能造成同样现象；
3. 是否存在更简单的解释或基线；
4. 计划中的实验能否真正区分这些解释；
5. 当前证据支持到“假设、实现、诊断、验收、结论”中的哪一层；
6. 哪个最小实验能够证伪它。

质疑必须来自理论、数学、文献、代码、数据或实验，而不是为了显得独立而反对。

## 3. 解释复杂内容的固定顺序

默认按下面顺序解释：

```text
解决什么问题
→ 直觉是什么
→ 为什么需要
→ 具体怎么做
→ 数学如何表示，每个变量是什么
→ 代码在哪里实现，实际输入输出是什么
→ 会影响哪个实验和指标，怎样被证伪
```

如果只需要其中几层，可以省略无关部分；但不能只堆术语、只给公式，或用一个术语解释另一个术语。

## 4. 回答项目问题的固定检索顺序

1. 从 `PROJECT_INDEX.md` 和 `RESEARCH_STATUS.md` 确认当前阶段和边界；
2. 用 `CODE_INDEX.md`、`EXPERIMENT_INDEX.md`、`RESULTS_INDEX.md` 或机器注册表定位对象；
3. 历史问题查询 `historical_method_registry.json`；
4. 常见问题可运行 `python code/scripts/query_project_knowledge_v1.py --query "问题"`；
5. 涉及科研判断时回到代码、配置、manifest、metrics、checkpoint 或 audit 核实；
6. 回答中明确区分已确认、候选、未知、阻塞和不能推出的结论。

ChatGPT 新对话先读 `AI_CONTEXT/00_PROJECT_STATE.md`；需要实现细节时按 `AI_CONTEXT/04_MODULE_MAP.md` 继续打开真实源码。

Windows 终端运行中文查询前设置 `$env:PYTHONUTF8='1'`，避免控制台编码造成乱码。

## 5. 禁止空泛表述

不能只说“提升鲁棒性、泛化能力或性能”。至少要说明：

- 对象：哪个状态、链路、任务或策略；
- 条件：哪个数据划分、seed、扰动或分布；
- 机制：为什么理论上可能改变；
- 指标：用什么量衡量；
- 对照：相对哪个基线；
- 边界：证据还不能说明什么。

## 6. 持续维护义务

新增或改变重要方法、实验、结果、配置、路径、冲突或结论时，必须同步更新对应人工注册表和导航文档，然后运行：

```powershell
python code/scripts/build_project_knowledge_index_v1.py
python code/scripts/build_project_knowledge_index_v1.py --check
```

索引只负责导航。原始证据仍负责最终验证。

每个有效任务还必须做 Context Consistency Check，只更新受影响的 `AI_CONTEXT/` 文件；验证合理后由 Codex commit 并 push，使 GitHub 与本地可信状态同步。
