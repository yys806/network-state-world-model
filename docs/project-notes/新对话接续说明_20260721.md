# PI-JWM 新对话接续说明

更新时间：2026-07-21

> 本文件用于让新的对话快速、准确地接续项目。它记录已经验证的事实、实验边界和代码入口，但不预先指定下一种方法。新对话可以从文献、问题定义、候选动作、selector 或 world model 接口重新提出方案，只要不破坏数据隔离和证据口径。

## 1. 项目是什么

PI-JWM（Physical-Information Joint World Model，物理--信息联合世界模型）研究 UAV-assisted vehicular fog/edge computing 中动作条件下的系统状态演化与调度决策。

系统包含以下相互耦合的对象：

- 车辆、UAV、RSU 等节点的移动、位置、覆盖和物理关系；
- 链路 activity、通信速率、RB 分配和传输过程；
- 任务生成、卸载、计算、结果回传和完成/失败状态；
- CPU、RB、offload target、return route 等调度动作；
- UAV 飞行、悬停、感知、接收和发送能耗。

PI-JWM 是项目主框架。AirFogSim 只是参考仿真器、数据源和 counterfactual rollout 环境，不能把 AirFogSim 写成本文方法。WaveFarer 软件和对应目录、旧数据集构建任务已经按用户要求清理，不要重新引入。

当前研究版本仍称为 **v11 candidate**。不能因为出现较好 validation 结果就改名为 v12，也不能把 selector 写成已经定型。

## 2. 当前研究问题

已经确认 world model 在获得可靠 future action condition 时具有明显更好的预测上界；当前主要困难不是简单继续增加 world-model 容量，而是：

1. 如何生成物理上合法、落在数据支持域内、并能真正改变环境状态的 future action；
2. 如何预测一个候选动作相对稳定默认动作的实际收益和风险；
3. 如何在不使用 future truth、counterfactual outcome 或 seed 身份的情况下选出候选；
4. 如何同时保留 active-rate、activity、link、task、resource 和 UAV energy 的解释链；
5. 如何在不确定时安全回退，而不是为了执行率强行选择动作。

可以把当前接口抽象为：

```text
历史状态与当前可观测上下文
    -> 生成并投影可执行候选动作
    -> frozen PI-JWM / actual simulator rollout 产生训练或审计标签
    -> 估计候选 benefit、risk 与不确定性
    -> selector 选择候选或 defer 到稳定基线
    -> 用任务、链路、资源和能耗分项解释结果
```

这只是问题接口，不是指定算法。新对话可以重新设计候选表示、学习目标、规划器、因果估计、校准方式或安全规则。

## 3. 必须继承的实验口径

### 3.1 数据 split

- selector train：seeds `0-15, 20-43`，40 seeds；
- calibration：seeds `44-49`，6 seeds；
- validation：seeds `50-59`，10 seeds；
- world-model validation：seeds `16-17`，只作背景检查；
- historical matched test：seeds `18-19`，早期冻结实验曾访问过，后续 refinement 不得再次用于调参；
- external holdout：seeds `60-69`，目前仍未访问。

当前正式迭代不能为了得到更好数字重新打开 seeds 18--19，也不能在结构和阈值冻结前访问 seeds 60--69。新方法应先用 train/calibration/validation 建立完整证据链。

### 3.2 结果标签

- `deployable`：测试时只用可获得特征，且没有在测试集选择配置；
- `true_future_reference`：使用真实未来动作或真实未来信息的参考上界；
- `sample_oracle`：逐样本事后选择，仅表示候选 headroom；
- `diagnostic_only`：用于归因、消融、敏感性或未完成独立测试的方法；
- `external_holdout`：配置冻结后一次性外部评价。

Oracle、test-best、true-future 和 diagnostic 结果不能写成自主可部署结果。

### 3.3 在线可用信息

测试时不得使用：

- seed 身份；
- 真实 future action 或 future state；
- AirFogSim counterfactual outcome；
- 候选真实 improvement/regret；
- `action_applied` 等只有 rollout 后才知道的结果标签。

真实 UAV energy 当前主要用于 audit。在线安全门使用可部署 task/energy proxy，不能把 proxy 冒充真实物理能耗。

## 5. 当前最可靠的根因判断

### 5.1 候选空间不是当前唯一瓶颈

当前 validation candidate gate：

- sample-oracle RMSE：`105.3486`；
- nontrivial ratio：`83.69%`；
- identity oracle-win ratio：`25.75%`；
- action-applied ratio：`100%`。

候选集合中存在大量潜在改善，selector 没有稳定识别出来。

### 5.2 失败不只是 defer 太保守

对正式 36 个 CandidateSet checkpoints 做 12 配置 x 6 决策规则归因后发现：

- rank-only validation RMSE 约为 `292.90-312.33`；
- 10 个 validation seed 全部恶化；
- 正收益精度只有约 `24%-29%`；
- 负选择率约为 `47%-54%`。

因此不能通过简单放松 defer、去掉 uncertainty 或关闭 Pareto 来修复。候选排序本身存在问题。

### 5.3 opportunity 可识别，候选内排序困难

schema-v6 交互审计显示：

- opportunity ROC-AUC：`0.8752`；
- opportunity PR-AUC：`0.9495`；
- candidate sign PR-AUC：`0.4754`；
- sample rank Spearman：`0.0832`；
- top-1 positive ratio：`0.2825`。

这支持“先判断是否存在改善机会，再解决候选内 benefit 排序”的问题分解，但不要求下一方法必须采用某一种两阶段网络。

### 5.4 episode phase 是有效但可能脆弱的上下文

每个 seed 有 390 个连续样本，`sample_id mod 390` 可以恢复 episode local step，而不直接暴露 seed 身份。phase-aware 诊断带来了显著 validation 改善，但 exact phase table 可能利用固定仿真时间结构，跨场景、变长 episode 和 external seeds 的稳定性尚未证明。下一对话应把它视作线索和基线，而不是必须保留的最终机制。

## 6. 已经试过且不应无理由重复的路线

以下方法在当前协议下没有稳定解决问题：

- 直接 behavior cloning；
- 六个独立 value-bin 分类和简单 class-balanced loss；
- 继续扩大旧 `top-k/alpha/cap` 模板网格；
- 只使用 global/action-summary 特征的 pairwise、pointwise 或 listwise selector；
- 正式 CandidateSetBenefitRanker，validation 100% defer；
- rank-only 或简单放松 uncertainty/defer；
- 无 phase 的 token interaction ranker；
- candidate-specific experts；
- learned residual routing；
- phase smoothing；
- estimator ensemble；
- phase-restricted kNN；
- 仅靠扩大 GPU、epoch 或训练样本数量。

这些不是永久禁止。新对话若要重试，必须指出与旧实验相比改变了哪个关键假设、如何用小规模证据证伪，以及为什么不是重复消耗算力。

## 7. 上周能耗与逐步 reward 工作如何接入

能耗、逐步 reward 和 horizon 诊断已经完成并写入可复现 artifacts：

```text
代码/artifacts/reports/pi_jwm_energy_reward_diagnostic_20260713/
代码/artifacts/reports/pi_jwm_energy_reward_horizon_study_20260713/
```

主要结论：

- seeds 0--4、15 个配对决策组中只有 7 个存在非平凡 task-utility 差异；
- horizon `3/10/20` 下仍是 7/15，单纯延长观察窗口没有提高候选区分度；
- 当前 CPU-scale 和 return-route 候选没有产生可观测差异，但这只说明当前决策点/动作幅度/单步注入协议不足，不能证明长期无效；
- offload 与 mixed offload-RB 存在中期负效应和后续部分补偿；
- UAV 能耗被拆成飞行、悬停、感知、接收和发送五类，并通过守恒检查；
- 真实 task/energy 只用于训练审计和物理解释，不能作为测试时不可获得的输入。

这部分的作用不是给 selector 强行添加一个综合 reward，而是帮助判断候选在哪个阶段生效、是否违反 task-energy Pareto、安全回退是否合理。

## 8. 最新文献边界

近期文献已经覆盖很多看似新颖的单点：

- FlexEdge：digital twin + UAV-VEC + PPO + 轨迹/资源/能耗；
- RADiT：digital-twin-driven IoV + UAV + DRL + energy/delay/task；
- `Agentic World Modeling for 6G`（arXiv:2511.02748）：action-conditioned dynamics、PRB 控制、uncertainty、what-if、MPC/CEM 和 offline policy screening；
- `Vision-Language-Action Models Meet World Models`（arXiv:2606.11618）：低空无线网络中的 UAV action--environment coupling、policy verification 和 dynamic optimization；
- decision-focused learning、offline RL、policy rollout、selective prediction 和 candidate ranking 本身也都有成熟先例。

因此不能把以下单点写成项目独有创新：digital twin、world model、action-conditioned rollout、PRB planning、policy screening、energy-aware UAV offloading、PPO/MAPPO、Pareto、uncertainty/defer 或 listwise ranking。

目前较可辩护的潜在差异是更窄的组合：

- 面向 UAV-assisted vehicular fog/edge 的物理--信息联合状态表示；
- activity、rate magnitude、task、resource 等多头 action-conditioned rollout；
- offload/RB/CPU/return 的可执行耦合候选协议；
- AirFogSim 对齐的 task-energy/逐步 reward 审计；
- 测试时不使用 simulator outcome 的 benefit/risk selector；
- 通过 counterfactual 实验把瓶颈定位到 action value/magnitude，尤其是 `rb_total`。

正式论文只能使用“据我们检索到的公开文献，尚未发现同时结合这些具体组成的统一框架”之类的限定表达，不能写“首次”或“没有人做过”。完整调研记录见根目录 `findings.md`。

## 11. 下一对话应保持开放的问题

以下问题没有被当前结果定死：

1. 下一步应优先改候选生成、收益标签、selector 表示，还是重新定义决策目标？
2. active-rate RMSE 是否仍应是唯一主门槛，还是应采用受 activity/task/energy 约束的分层目标？
3. 是否应从逐候选排序改成 opportunity detection + 局部 repair、直接预测 paired delta、conformal risk control、MPC/CEM、因果/uplift 方法或其他路线？
4. exact episode phase 是否可替换为可泛化的任务阶段、队列状态、拓扑变化或事件时间特征？
5. 候选 oracle 很强而排序很弱，究竟来自标签噪声、局部交互表示不足、样本权重与 RMSE 不对齐，还是跨 seed 分布漂移？
6. 应如何构造持续多步候选，使 compute/return 动作真正改变状态，而不是只扩展相同 horizon？
7. 独立 external holdout 的解锁门槛是否仍应坚持 validation `<200`，还是在新研究问题下重新预注册一套合理门槛？

新对话可以重新回答这些问题，但必须先区分：已有事实、合理解释、待验证假设。

## 12. 建议的新对话启动顺序

1. 先阅读本文件、`AGENTS.md`、`progress.md`、`findings.md`、`task_plan.md` 和正式 selector `summary.json`；
2. 运行 `git status --short`，确认不覆盖已有修改；
3. 根据最新文献和数据证据，重新提出 2--3 条相互有区别的方法路线，不默认沿用 phase LCB；
4. 明确每条路线相对既有失败实验改变了什么假设；
5. 先设计最小 CPU 证伪实验和停止条件，再决定是否需要 GPU；
6. 在 validation 冻结前不访问 matched test/external holdout；
7. 只有独立结果达到预注册门槛后，才更新“最终 selector”或版本命名。
