# PI-JWM 项目重构实施计划

## 目标

建立一套让用户逐步重新掌握科研内容、让 AI 能够快速检索和长期维护的项目知识结构；不改变研究问题、算法原理、模型、loss、指标、实验目的或已有结论。

## 已确认约束

- 当前远端 GPU 正式训练已结束，正式产物已回传；同步相关目录仍按保护对象处理，未确认静止前不做结构迁移。
- `code/artifacts/` 中的训练、同步、checkpoint、tensor、manifest、协议和原始结果是保护对象。
- 归档优先于删除；历史失败实验和旧配置必须可追踪。
- 索引用于导航，原始代码、配置、日志、metrics、checkpoint 和 audit 用于验证。
- 当前 P4 未关闭，P6 未开放，`locked_test` 封存。
- 本轮不重复执行 2026-08-16 已完成的顶层目录迁移，不移动 RRM，也不恢复已删除的旧资料。

## 阶段 1：安全导航层（已完成）

只新增或小范围补充导航文档：

- 项目地图：`docs/PROJECT_INDEX.md`；
- 架构说明：`docs/ARCHITECTURE.md`；
- 当前科研状态：`docs/RESEARCH_STATUS.md`；
- 实验索引：`docs/EXPERIMENT_INDEX.md`；
- 结果索引：`docs/RESULTS_INDEX.md`；
- 结构变更记录：`docs/CHANGELOG.md`；
- 本实施计划：本文件。

阶段 1 不移动、不重命名、不删除任何已有文件，不写入当前训练证据目录。

## 阶段 2：只读证据映射

在确认同步静止后，生成可审计的文件/实验映射：

- 当前代码入口、测试覆盖和脚本入口；
- 实验 ID、研究问题、配置、数据、checkpoint、结果和 audit；
- 历史方法、失败原因和替代关系；
- 文档之间的权威关系和冲突清单。

这一步仍不移动原始 artifact；映射必须包含路径、状态和必要的 SHA-256。

## 阶段 3：受控归档和去重

只有满足以下条件后才讨论移动或归档：

1. 远端训练结束，正式目录已发布；
2. 同步过程静止，相关文件不再变化；
3. 用户确认迁移范围；
4. 生成逐文件映射、哈希、冲突检查和回滚脚本；
5. 分批迁移，每批完成后验证路径、引用、测试发现和 evidence manifest。

任何删除都必须先有明确的科研价值判断、归档副本和可恢复记录。

## 阶段 4：持续维护

以后新增算法、实验、结果、配置、路径或结论时，同步更新相应索引；涉及理论边界或正式性能时，还必须更新现有 `记录/` 权威文件。重要改动完成后检查代码、实验、结果、文档和索引是否一致。

## 回滚原则

- 第一阶段索引文件可单独删除或回退，不影响训练和原始证据。
- 未来迁移必须依据本轮映射逐文件反向恢复，不使用宽泛递归删除。
- 若验证发现 layout-induced 证据错误，立即停止后续迁移，保留失败现场并报告。
