# PIJWM V2U4Real Label Merge Policy V1

状态：**冻结**（2026-10-27，研究者明确选择方案 B）

策略类型：**implementation-faithful policy（实现行为复现策略）**

## 目的与范围

本合同规定 PIJWM 后续复现 V2U4Real 官方单 ego + UAV 标签合并流程时的对象来源优先级。它只冻结“同一个对象 ID 从哪一端保留”的规则，不冻结框角度、尺寸、中心字段的物理语义，也不构成点云、位姿、标定或真实同步验收。

适用于官方仓库 VjiaLi/V2U4Real 固定 commit e099a3a746c6092a614e18b74d1f5b2f3c8351e8 的转换器行为。当前核验数据来自 VJiaLi/V2U4Real，数据版本 36f64423a639db7c5bbc8ac8575b1ee74d7b8e9a。当前五帧核验场景为 `train/2025-07-18-12-53_2`，车辆 agent `1`、UAV agent `2`，传感器 `ouster`。

## 决策与证据

研究者在 R2-04C 指令中明确选择**方案 B：以官方转换器实际行为为准**。本选择是本合同的正式决策记录，不是 Codex 根据工程方便推断的决定。

固定源码：

- 仓库：`https://github.com/VjiaLi/V2U4Real`
- commit：`e099a3a746c6092a614e18b74d1f5b2f3c8351e8`
- 文件：`opencood/utils/uav_to_single.py`
- SHA-256：`cab7b48fe7c343cbb356db131cd1b87f64249f9cfcb7b4073fdeac18ed51ec4b`
- 关键行为：先 `merged_objs.update(ego_objs)`，然后遍历 `uav_objs` 执行 `merged_objs[oid] = obj`（固定源码第 190–199 行）。

这是 **implementation-faithful policy**：复现固定版本官方实现行为，**不声称它与论文所有文字描述完全一致**。论文 §4.2 描述同一对象存在偏移时保留 ego/车辆框，而官方转换器同 ID 由 UAV 对象覆盖。本合同遵循研究者选择的官方代码行为，不修改官方源码来消除冲突。

## 冻结规则

| 输入情况 | 处理 | 最终来源 |
|---|---|---|
| ID 同时出现在车辆和 UAV | 先放入车辆对象，再由 UAV 对象覆盖 | UAV |
| 只出现在车辆 | 保留 | 车辆 |
| 只出现在 UAV | 保留 | UAV |
| 两端都无对象 | 输出空集合 | 无 |

合并结果满足：

```text
I_out = I_vehicle ∪ I_uav
I_vehicle ∩ I_uav => final_source(ID) = UAV
```

ID 匹配采用 Python/YAML 映射键的原始相等语义。流程不得把字符串 ID 转成整数、去除前导零、大小写规范化或按字符串格式重写；官方实现没有做这些操作。空间相近但 ID 不同的对象不得自动合并。

同 ID 冲突时不平均中心、不平均尺寸、不仲裁角度、不比较点云覆盖、不使用中心距离或“看起来更准确”重新选择来源。车辆独有和 UAV 独有对象都必须保留。

## 追溯要求

每次实际复现都必须保存：

1. 两端 YAML 的路径、文件大小、SHA-256 和读取状态；
2. 车辆 ID 集合、UAV ID 集合、共有/独有集合；
3. 每个最终对象的 `final_source`；
4. 同 ID 被覆盖时的车辆原始对象、UAV 原始对象和最终对象；
5. 合并前后数量及集合关系检查；
6. 原始标注不能被删除、覆盖或写回。

R2-04C 复用 R2-04A 已核验的固定源码函数加载器，实际执行官方 x1_to_x2(uav_pose, vehicle_pose) 和 load_annotation_objects，再按官方顺序合并。车辆不叠加相对变换，UAV 对象转换到车辆参考系。所有转换对象标记 official_code_interpretation_only，原始字段单独保留；这不冻结字段的物理解释。结果目录保存五帧逐对象追溯；模拟只在内存中运行，没有生成正式训练标签文件。

## 明确未解决的语义边界

本合同不解决：

- 论文 `(roll,pitch,yaw)` 与官方代码 `[roll,yaw,pitch]` 的顺序差异；
- `location`、`center`、`extent`、`angle` 的完整字段语义、单位和轴顺序；
- 两端框尺寸不一致的原因；
- 论文所述跨端 IoU 匹配、ID 统一和补充标注与当前转换器行为的完整关系；
- 发布点云/位姿的真实物理轴向、预定义轴变换系数及应用阶段；
- RTK/GICP/人工配准修正来源、物理时间同步和样本级真实标定。

同 ID 对象经过共同转换流程后中心距离较小，只能作为内部追溯观察，不能当作独立物理标定真值。UAV 优先只表示标签来源优先级，不表示 UAV 点云、位姿或标定天然更准确。

## 修改门

任何改动本合同优先级、ID 语义、单端保留规则或与论文冲突的处理方式，都必须获得研究者明确授权，并更新本合同版本、来源证据、机器审计和相关 R2-05 协议。不得由后续脚本、模型训练或指标异常自动改写。
