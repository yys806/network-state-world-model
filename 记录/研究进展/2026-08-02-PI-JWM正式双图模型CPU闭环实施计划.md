# PI-JWM正式双图模型CPU闭环实施计划

> **执行要求：** 按任务顺序推进；每个功能先写失败测试，再写最小实现，最后运行相关回归测试。CPU阶段只使用`train`、`validation`和`calibration`，禁止读取`locked-test`。

**目标：** 在正式AirFogSim双图张量上跑通PI-JWM严格双图的动作条件三步预测，并让规则基线、通用学习基线和耦合模型通过同一数据、损失与指标协议产生可审计结果。

**实现原则：** AirFogSim只提供仿真数据；正式模型、训练器和评价器均位于PI-JWM代码目录。任务/DAG是辅助结构，不改写成信息图节点或边。CPU结果只证明接口和计算链路成立，不用于宣称最终模型优越性。

**技术栈：** Python、PyTorch、NumPy、标准库`unittest`；不新增图学习依赖，稀疏聚合使用PyTorch原生`index_add_`。

## 任务3：三类学习模型与动作条件rollout

**文件：**

- 新建：`代码/src/pi_jwm/formal_dual_graph_world_model_v1.py`
- 新建：`代码/tests/test_formal_dual_graph_world_model_v1.py`

**步骤1：先写失败测试**

为`pooled_gru`、`independent_dual_gnn`和`coupled_dual_gnn`共用同一合成batch，验证：

- 输入8步历史与3步未来动作，输出严格为3步。
- 四类连续状态均输出`mean`和截断后的`log_variance`。
- 输出节点/边/流/任务存在性、链路活动、任务生命周期、DAG状态和DAG释放概率。
- 前向值有限、反向传播有非零梯度。
- 改变未来动作会改变预测；改变未来真实状态不会影响输入和预测。
- `independent_dual_gnn`关闭CIP/CFE/任务跨图耦合，`coupled_dual_gnn`打开三类耦合。
- `physical_only`、`information_only`、`no_dag`、`no_cpu_action`和`no_cross_coupling`开关均可完成前向。

**步骤2：实现配置与共享接口**

```python
@dataclass(frozen=True)
class FormalWorldModelConfig:
    mode: Literal["pooled_gru", "independent_dual_gnn", "coupled_dual_gnn"]
    hidden_dim: int = 16
    history_steps: int = 8
    horizon_steps: int = 3
    use_dag: bool = True
    use_cpu_action: bool = True
    use_cross_coupling: bool = True

class FormalDualGraphWorldModel(nn.Module):
    def forward(self, batch): ...
```

节点、物理边、信息流、任务、DAG派生状态和动作分别由小型MLP编码；每类实体通过共享GRU编码8步历史。`pooled_gru`只使用masked pool；两个GNN模式使用任务2的真实端点聚合。

**步骤3：实现三步共享参数rollout**

每一步先编码给定动作，并按任务动作端点写入任务、代理和物理节点latent；随后执行物理图、信息图、DAG和可选跨图耦合；再由统一预测头输出该步状态分布与离散事件。下一步只使用模型latent，不读取真实未来状态。

## CPU阶段完成标准

只有同时满足以下条件，才把本地阶段标为完成：

1. 正式窗口明确提供历史、未来动作、目标和DAG辅助状态，且无未来状态泄漏。
2. 三种学习方法及两种规则方法通过统一接口；学习方法前向、反向和多步rollout均有限。
3. 严格物理图、信息图、CIP、CFE和任务/DAG辅助关系均由真实索引参与计算。
4. 完整指标注册表对可计算项给出数值和证据，对不可计算项给出原因。
5. 正式数据上的interface smoke和comparison smoke均产出可复算artifact与manifest。
6. 所有新增测试、相关回归、编译和差异检查通过。
7. `locked-test`始终未读取，且CPU短训练结果未被表述为最终性能结论。
