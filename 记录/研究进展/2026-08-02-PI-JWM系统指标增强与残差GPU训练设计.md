# PI-JWM系统指标增强与残差GPU训练设计

## 1. 目标与边界

本轮采用“先A、再B”的方案。阶段A不重建5.28 GB正式原始数据，直接复用当前10440/3480/1740个非锁定train/validation/calibration窗口，补齐已可计算的系统指标汇总，并训练末值残差版严格双图模型。阶段B在阶段A运行期间审计并扩展正式张量，使端到端时延、UAV能耗和服务公平性能够由真实字段计算。locked-test在两个阶段中继续不张量化、不上传、不访问。

本轮不把“任务状态中的delay误差”等同于“端到端P95/P99完成时延”，不把链路速率总和等同于应用层有效吞吐量，不用能耗代理值替代AirFogSim能量账本，也不把一个训练seed解释为统计显著性结果。

## 2. 阶段A：现有正式张量上的立即增强

### 2.1 系统指标汇总

现有评价器已经能够从预测状态和真实目标中计算以下指标，但上一版`comparison.csv`只展示链路F1和节点位置误差。本轮将统一汇总：

- 物理链路：链路F1/AUPRC、active-only速率MAE/RMSE、系统通信吞吐量MAE；
- 任务时序：任务delay MAE/RMSE、deadline remaining MAE/RMSE、任务生命周期macro-F1；
- 系统结果：任务完成率绝对误差、RB占用MAE；
- DAG：释放事件F1、未完成父任务数量MAE；
- 不确定性：delay、deadline、吞吐相关状态的NLL、95%覆盖率和区间宽度。

P95/P99完整完成时延、UAV能耗和服务公平性在阶段A继续输出`not_computable`及准确原因。

### 2.2 末值残差模型

新增`residual_state_prediction`配置。学习模型不再直接输出未来绝对连续状态，而是输出相对历史最后一个有效状态的增量：

$$
\widehat{\mathbf s}_{t+k}=\mathbf s_t+\Delta\widehat{\mathbf s}_{t+k}.
$$

每个预测步都以同一个决策时刻末值为基准，避免把误差递归累积；新出现且历史中不存在的实体以零基准和有效掩码处理。概率方差仍由原分布头输出，存在、链路活动、生命周期和DAG事件头不变。

为了避免连续状态平均损失淹没稀疏但重要的系统量，损失函数新增三个可审计辅助项：真实活动链路上的条件速率MAE、任务delay MAE、任务deadline remaining MAE。所有项只使用train标签和既有掩码，不引入validation或calibration信息。

### 2.3 公平比较

保留上一轮五种方法及其冻结结果，新增两个残差消融：

1. `independent_dual_gnn_residual`：无CIP/CFE跨图耦合；
2. `coupled_dual_gnn_residual`：启用CIP/CFE跨图耦合。

两者使用相同seed、初始化、参数量、数据顺序、hidden=64、batch=32、20轮和validation选模协议。这样可以分别判断残差结构是否有效，以及在相同残差结构下跨图耦合是否仍有收益。阶段A成功门为：残差模型至少在validation和calibration两个split上同时改善节点连续状态、任务delay或系统吞吐量中的两类指标，同时不使链路活动F1低于对应绝对值模型；否则保留为失败消融。

## 3. 阶段B：完整时延、能量与公平性字段

### 3.1 优先复用现有正式原始轨迹

正式原始轨迹已包含任务到达/完成状态、`task_delay`、UAV逐时隙能量账本和任务源节点。阶段B先从现有产物派生标签，不重新运行AirFogSim；只有独立字段审计确认某个split缺失必要原始行时，才重跑受影响轨迹。

新增独立`system_target`，不把系统量混入物理图或信息图定义：

| 字段 | 真实来源 | 用途 |
| --- | --- | --- |
| `task_completion_event` | 任务生命周期首次进入finished | 完成事件F1和完成率 |
| `completed_task_delay` | AirFogSim任务完成时的`task_delay` | 平均/P95/P99时延 |
| `uav_energy_delta` | `energy_before-energy_after` | 能耗MAE与能量守恒 |
| `source_service_delta` | 各任务源节点本时隙完成任务数 | Jain公平性 |
| `delivered_data_total` | 实际信息流本时隙交付量 | 应用层有效吞吐量 |

### 3.2 评价协议

端到端系统指标采用逐轨迹的一步滚动事件评价：每个真实时刻只取一个窗口的`k=1`预测，根据“历史末时隙未完成、下一时隙预测为finished”判定预测完成事件，并以`seed+task_id`去重。由去重后的真实/预测完成事件分别计算平均、P95和P99时延。该口径评价的是观测历史条件下的一步滚动系统结果，不冒充完全自主的30秒闭环rollout。

UAV能耗按节点—时隙掩码评价MAE/RMSE和总量误差；应用层吞吐量按实际交付数据量除以时隙长度计算；公平性在每条完整轨迹的固定源节点集合上，根据预测完成任务数计算Jain指数及其绝对误差。能量方程、任务流和资源容量违例率继续作为硬验收门。

### 3.3 模型接口

任务完成事件继续由生命周期头给出，完成时延继续使用任务delay状态头；新增节点级UAV能量增量分布头。应用层吞吐量由预测信息流`delivered_this_slot`聚合，不新增重复输出头；公平性由完成事件和任务源节点索引派生，不直接训练“公平性分数头”。这种设计使指标能够回指真实状态和事件，避免为得到好看的系统指标再造不可解释的代理输出。

## 4. 产物与验证

阶段A输出新的七方法比较表、完整系统指标表、训练历史、最佳检查点、运行时、严格JSON和SHA-256清单。阶段B输出字段审计、正式张量新版本、逐轨迹事件评价、时延/吞吐量/能耗/公平性报告和新清单。

所有新增行为采用测试先行：先验证残差零增量等于末值保持、活动速率掩码、系统汇总字段、完成事件去重、P95/P99口径、UAV掩码、Jain公平性和locked-test拒绝；观察测试按预期失败后再实现。完成后运行正式模块回归、编译检查、产物哈希复算和检查点重载。第一阶段GPU训练启动后，阶段B只进行CPU数据审计与构建，不并发占用同一GPU。

## 5. 当前确认状态

- 采用方案C：阶段A完成并启动GPU后继续阶段B。
- AirFogSim仍只是仿真与数据来源，PI-JWM是框架和模型主线。
- Coupled-JEPA完整论文方法不在本轮残差修复中冒充完成；待系统指标和基础rollout稳定后单独适配。
