# PI-JWM R5 CPU组合预检设计

日期：2026-08-05

## 1. 目标与边界

R5 CPU阶段只为正式多seed GPU训练准备可审计入口，不训练收敛模型，不比较性能，不访问locked-test。它复用R1数据、R2评价协议、R3公共状态接口和R4已实现模块，解决两个前置问题：一是把R4单模块结果收缩为有限组合；二是证明组合中的每个模块真实执行、产生梯度并可严格保存/重载。

R4工厂继续保持“参考配置加至多一个变化模块”的约束，以保证R4正式结果可复现。R5新建独立白名单组合层，不修改R4候选含义，也不允许任意笛卡尔积。

## 2. 固定组合

| ID | 配置 | R5问题 |
| --- | --- | --- |
| A | 参考Graph-GRU＋确定性头＋DAG摘要＋固定观测presence | 正式控制组 |
| B | Graph-RSSM，其余同A | R4首选动力学能否跨seed稳定 |
| C | Graph-RSSM＋异方差输出头 | 概率输出能否改善NLL、覆盖率和区间质量 |
| D | Graph-RSSM＋显式DAG消息传递 | 任务依赖传播能否改善任务演化 |
| E | Graph-RSSM＋soft predicted presence | 预测拓扑递归能否改善动态图rollout |

组合只能通过ID构造。C必须同时输出RSSM prior/posterior参数和七组连续状态log variance；D必须在Graph-RSSM的基础图状态推断中执行DAG有向消息；E必须在Graph-RSSM所用的基础rollout中从第二步开始使用预测presence。任何名称与实际后端不一致均视为失败。

## 3. 组合架构

Graph-RSSM后端改为可接收一个符合R3公共接口的基础图后端，默认仍使用原R3后端，因此R4的B臂行为不变。D和E分别将显式DAG后端、soft presence后端注入Graph-RSSM。C在Graph-RSSM输出之外增加异方差装饰器，不替换RSSM动力学，并把两类概率参数合并到同一个公共输出。

R5公开模型继续返回`predicted_explicit`、`predicted_logits`、四类`predicted_belief`、`probabilistic_parameters`和`execution_metadata`。R4目标函数已经能同时识别RSSM KL与异方差NLL，R5直接复用，不复制损失公式。

## 4. 正式协议

- 训练seed固定为`20260803/20260804/20260805`。
- 每个组合最多100 epoch，patience 10，有效batch size 32，minimum improvement `1e-4`。
- 所有组合与seed使用相同训练窗口和优化步数上限。
- validation只选择checkpoint；calibration只设置事件阈值、分布温度和共形分位数；locked-test在R9前禁止读取。
- 冻结综合分数继续报告，但不能单独定型。信息边活动AUPRC、活动速率MAE、任务生命周期macro-F1和连续状态归一化误差必须分别报告；概率候选另外报告NLL、95%覆盖率和区间宽度。

## 5. CPU验收

CPU预检从train、validation、calibration各取1/5/20步真实窗口。每个A-E组合在三个正式训练seed下至少执行一次前向、目标、反向和优化步骤，并检查有限/非零梯度、未来标签隔离、动作敏感性、公共输出完整性、候选专属模块参数与辅助目标、严格checkpoint回读和输入哈希绑定。validation公共四项必须可计算；C必须具有校准所需分布参数。CPU产物通过全部检查后只设置`r5_gpu_ready=true`，不输出获胜组合。

## 6. 产物

正式产物写入`代码/artifacts/preflight/pi_jwm_r5_cpu_preflight_v1/`，包括协议、组合矩阵、窗口、逐组合逐seed报告、目标、checkpoint、输入/源码溯源、GPU交接清单、失败记录和manifest。任何失败均保留报告并使阶段门关闭。
