# 完整 RSSM 论文对照与 PI-JWM 实现审计

日期：2026-09-05
状态：候选实现已完成 CPU 契约验证；尚未进行正式性能实验，不能称为最终方法。

## 结论

当前 `graph_rssm_v1` 不是空壳：它有随机状态、上下文先验、上下文后验和部署时的 prior-only 递推，也有有限的 KL 目标。但它没有闭合标准 RSSM 的训练证据链：上下文先验和后验使用同一个 `base_belief.joint`，未来每一步没有观测后验路径，KL 只覆盖上下文分布，且没有单独的多步 latent 监督。因此此前将它写成“Graph-RSSM 候选”是合理的，将它写成“完整 RSSM 世界模型”则证据不足。

补充审查发现，posterior 如果只进入 KL 而不进入观测/状态重构项，训练信号仍不完整。现已增加训练模式的 posterior-teacher 显式状态/分类输出：每个未来步的 posterior 读取对应 target observation，R4 目标保留自由 prior 重构并增加权重 `0.5` 的 teacher 重构；正式 `predicted_*` 输出仍只来自 prior rollout，验证和部署不读取 teacher。

本次新增 `complete_graph_rssm_v1`，保留 PI-JWM 的双图编码、动作条件、确定性规则/输出头和 mask 语义，补齐以下闭环：

1. 历史上下文产生确定性状态 `h`；
2. `p(z|h)` 与 `q(z|h,observation)` 使用不同条件；
3. 训练教师路径逐步读取目标观测，得到每个未来时刻的 posterior；
4. 预测路径只使用历史上下文、动作和 prior，目标及其 mask 不进入预测；
5. 目标加入逐步 KL、KL balancing 和自由 prior rollout 的多步一致性项；
6. 预测仍输出显式节点、边、流、任务和 DAG 状态，兼容现有 R4 目标与指标接口。

## 现有旧实现的缺口

文件：`code/src/pi_jwm/r4_world_model.py` 中 `_GraphRSSMBackend`。

- `context_prior` 和 `context_posterior` 都只接收 `base_belief.joint`，没有“当前观测进入 posterior”的条件差异。
- rollout 每步只产生 prior，没有与对应目标观测配对的 posterior sequence。
- `r4_objective.py` 只对四个 context distribution 参数计算 KL；没有逐步 KL，也没有 KL balancing。
- 显式状态损失虽然作用于自由递推输出，但没有明确记录它是 rollout-decoded reconstruction，也没有独立 latent 多步一致性项。
- 因此旧实现可作为历史候选和对照，不能作为完整 RSSM 的正式证据。

## 新实现的可核验证据

新增文件：

- `code/src/pi_jwm/complete_rssm_world_model_v1.py`
- `code/tests/test_complete_rssm_world_model_v1.py`

新实现保留旧模型的公共输出结构，并在 `probabilistic_parameters` 中显式记录：

- `context_prior_*`、`context_posterior_*`；
- `posterior_path_prior_*`、`posterior_path_posterior_*`；
- `rollout_prior_*`。

契约测试 5/5 通过：

- 逐步先验/后验形状正确，且训练 posterior 与部署 prior-only 元数据存在；
- 任意扰动未来 target 不改变预测 latent 和 `rollout_prior`；
- 逐步 balanced KL 与 overshooting consistency 可反向传播到 transition/prior/posterior；
- h20 输出有限，目标只改变训练 posterior，不改变部署 prior。
- 训练模式 posterior teacher 的显式状态/分类输出会随 target 改变，并由 R4 以权重 `0.5` 作为补充重构项使用；自由 prior 重构保留，部署可见 prior 输出对 target 扰动保持不变。

这些结果只证明“方法完整性接口已实现并可执行”，不证明性能改善，也不开放 GPU、follow-up seeds 或 `locked_test`。

## 进入正式性能实验前的条件

1. 将新模型接入一条独立的 CPU micro runner，保存模型身份、KL/overshooting/teacher reconstruction 权重、prior/posterior 语义和 strict reload 证据。
2. 在 canonical h20 tensor 上完成理论—代码—数据—指标一致性审计；尤其确认规则层在每个 rollout step 仍执行，target 不进入预测路径。
3. 只在 CPU 门通过后，按当前 P4 冻结协议运行单个 sentinel seed `20260831`；先性能门，后概率门，失败即停。
4. 只有 sentinel 通过，才允许 follow-up seeds；只有 P4 通过，才进入 P6 planner。

当前不把新模型替换为 P4 已失败的持久性残差结果，也不覆盖旧 checkpoint。两者作为不同方法身份分别记录。
