# PI-JWM v11 候选收益可辨识性审计设计

日期：2026-07-18  
状态：设计已确认，待实施计划复核  
方法身份：`v11 candidate` 的前置诊断，不是新 selector，也不是 v12

## 1. 背景与决策

schema-v5 正式 validation 的 ranked-allocation baseline active-rate RMSE 为 `234.2529`，32 候选 sample oracle 为 `105.9892`，best fixed candidate 为 `230.8556`。候选门全部通过，说明候选集合包含足够大的理论改进空间。

2026-07-18 的 objective-aligned selector 正式训练未能利用该空间：四个神经配置均 `100%` defer；解除 uncertainty 后 RMSE 恶化到 `255.058`；模型强制建议的候选中，正收益占 `32.19%`、负收益占 `42.70%`，预测收益与真实收益相关性为 `-0.0253`。不确定性回退正确阻止了伤害，但没有解决候选识别问题。

历史 RF/HGB/RF-value reconstruction 的跨 split 收益或 value 相关性通常只有约 `0.03--0.08`。因此，本轮停止继续增加神经网络超参、放宽 defer 阈值或打开锁定测试集，先回答一个更基础的问题：

> 在部署时可获得的 current state、历史动作、候选动作、PI-JWM forecast、stage、task/resource/energy proxy 中，是否存在跨 seed 稳定的候选收益信号？

只有先证明可辨识性，继续训练复杂 selector 才有依据。

## 2. 目标与非目标

本轮目标：

1. 量化不同合法特征组对 sample opportunity、候选收益正负和候选排序的独立贡献。
2. 判断失败属于整体状态观测不足、候选局部交互缺失、动作族异质性，还是现有神经训练问题。
3. 用简单、可解释模型建立跨 seed 下限，并生成是否进入下一轮 GPU selector 的硬门结论。
4. 若现有 schema-v5 不可辨识，给出最小 schema-v6 特征补充范围，不用更复杂模型掩盖输入不足。

本轮不做：

- 不重新训练 PI-JWM world model；
- 不重新生成 schema-v5 actual-rollout 标签；
- 不访问 matched seeds `18--19`；
- 不生成或访问 external seeds `60--69`；
- 不把 sample oracle、best fixed 或诊断模型描述为 deployable 结果；
- 不承诺本轮审计本身达到 RMSE `<200`。

## 3. 数据与泄漏边界

复用已冻结、带 SHA-256 的 schema-v5 缓存：

- train：seeds `0--15,20--43`；
- calibration：seeds `44--49`；
- validation：seeds `50--59`。

所有 normalization、缺失值处理、类别编码、阈值和模型拟合只使用 train。calibration 只允许选择预先固定的执行阈值；validation 只用于最终比较已冻结的审计配置。

严禁输入：

- seed 身份及其直接编码；
- future truth、actual counterfactual outcome、真实 future task/energy；
- candidate active SSE、真实 improvement/regret、oracle choice；
- 从 validation outcome 反推的阈值或特征选择结果。

允许输入仍限定为现有 schema-v5 的测试时可见字段：current/history state、候选动作摘要、默认与候选 PI-JWM forecast、stage、mask、selected-edge 当前状态聚合、task/resource/energy proxy。

## 4. 三层可辨识性问题

对 sample \(i\) 和候选 \(c\)，定义相对 ranked-allocation baseline 的真实 SSE benefit：

\[
B_{i,c}=\operatorname{SSE}_{i,d}-\operatorname{SSE}_{i,c}.
\]

定义 sample opportunity：

\[
G_i=\max\left(0,\max_{c\in\mathcal C_i} B_{i,c}\right).
\]

审计分成三个任务，避免用一个平均相关系数掩盖错误来源：

1. **Opportunity identification**：预测 \(G_i\) 是否超过 train-only 的实质收益门槛。
2. **Benefit sign identification**：预测合法候选是否满足 \(B_{i,c}>0\)。
3. **Conditional ranking**：在同一 sample 内，对合法候选按 \(B_{i,c}\) 排序。

`active_count=0` 的 sample 保留审计记录，但不进入 active-rate SSE 决策指标。候选 mask、动作适用性和动作真实生效条件继续沿用 schema-v5 协议。

## 5. 特征组与对照

按固定组逐步增加特征，所有组名和列清单写入结果 manifest：

1. `prior_only`：动作族、候选身份和 train-only 先验，作为最低对照。
2. `context_only`：current/history node、link、task、action 状态以及 stage。
3. `candidate_only`：RB/CPU/offload/return 动作量、三步模式、候选族和能耗代理。
4. `forecast_delta`：候选相对默认的 PI-JWM activity、rate、task-progress 预测差。
5. `selected_edge`：被修改边的距离、rate、CSI、active-task、allocated-RB 及预测响应聚合。
6. `full_schema_v5`：上述所有合法字段。

同时做固定消融：去掉 stage、task、resource、energy、selected-edge 和 forecast-delta。消融用于解释，不允许据此在 validation 上不断构造新组合。

## 6. 模型与评估协议

本轮优先使用简单模型回答“信号是否存在”，而不是追求模型容量：

- 常数/动作族先验；
- Logistic/Ridge；
- Random Forest；
- HistGradientBoosting；
- XGBoost（本地依赖可用时）；不可用则明确记录 `skipped_dependency_unavailable`。

训练内部使用按 seed 分组的交叉验证，任何一行不得随机拆分到同 seed 的训练和验证两侧。模型数量、主要参数和随机种子在实现计划中预先固定，不进行无界网格搜索。

核心指标：

- opportunity：ROC-AUC、PR-AUC、Brier score、逐 seed recall；
- benefit sign：PR-AUC、执行集 precision、negative-selection rate；
- conditional ranking：sample 内 Spearman、top-1 positive ratio、top-1 regret；
- 决策结果：active-rate RMSE、activity F1、link RMSE、逐 seed 改善数；
- 分层结果：stage、action family、gain decile 和 seed。

相关性只作为辅助结果。大量零收益和动作族不适用会使全局 Pearson/Spearman 失真，最终判断以 top-1 决策质量和配对 SSE/RMSE 为主。

## 7. 选择规则与硬门槛

每个模型输出 opportunity 概率、candidate positive-benefit 概率和条件 benefit。calibration seeds 只从预先固定的概率阈值集合中确定唯一执行阈值；未过阈值时回退到 ranked-allocation baseline。

允许进入下一轮 GPU selector 设计的最低门槛：

1. validation active-rate RMSE `<230.8556`，即严格优于当前 best fixed candidate；
2. validation 至少 `7/10` seeds 优于各自 ranked baseline；
3. 被执行候选的正收益 precision `>=65%`；
4. 被执行候选的负收益选择率 `<=20%`；
5. activity F1 下降不超过 `0.002`，link RMSE 相对恶化不超过 `2%`；
6. 所有结果通过泄漏、确定性和聚合重算审计。

达到以上门槛，说明 schema-v5 已存在可用收益信号：冻结表现最简单、跨 seed 最稳的模型作为 selector 下限，再设计候选集合模型；此时才需要 GPU。

未达到门槛，则停止 schema-v5 selector 训练。根据审计定位增加最小 schema-v6 特征，优先方向为“被修改 edge-step 的局部状态—动作—预测响应”交互，而不是继续增加全局均值或模型深度。schema-v6 必须重新生成 train/calibration/validation 标签并重新审计，仍不打开 locked splits。

## 9. 测试与执行边界

测试至少覆盖：

- seed split 无交叉及 group CV 无泄漏；
- 禁止 future/oracle/seed 特征；
- benefit、opportunity、regret 和 active-rate RMSE 重建；
- mask、零 active count、零 benefit、全同候选；
- train-only normalization 和 calibration-only 阈值；
- 同 seed 确定性；
- 每张汇总表可由 prediction trace 重算。

先在本地 CPU 完成单测、64/256 sample smoke 和正式 schema-v5 审计。简单模型审计不需要 GPU。只有审计过硬门、需要训练新的 candidate-set selector 时，才启用服务器 GPU。

## 10. 解释口径

本轮可能产生三类结论：

- **可辨识**：简单模型跨 seed 过门，说明收益信号存在，神经 selector 的目标或训练结构是主要瓶颈。
- **局部可辨识**：只有特定 stage/family 过门，下一轮采用 stage/family routing，不声称统一 selector 已解决。
- **不可辨识**：所有合法 schema-v5 特征均不能稳定预测收益，说明需要补充局部交互观测或重新定义候选，不再用 GPU 超参搜索掩盖输入问题。

任何结果都继续标记为 `diagnostic_only`，直至新的 selector 独立 validation 达标并完成正式冻结。
