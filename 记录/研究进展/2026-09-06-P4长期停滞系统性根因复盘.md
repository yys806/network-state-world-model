# P4 长期停滞系统性根因复盘（2026-09-06）

## 结论

P4 长期停滞不是一个模型模块或一个超参数造成的。现有证据显示，问题由五层因素叠加：P4 内部验收对象持续变化；早期数据与实现合同不完整；复杂模型使用过小且未收敛的 sentinel 预算；训练目标、checkpoint 选择和最终性能门不一致；物理位置与稀疏链路任务本身存在信息和优化难题。过去按“本次哪项指标失败就修哪项”的方式推进，形成了串行补丁循环。该方式现在停止。

## 已确认的事实

1. 正式 tensor 有 `14742` 个 unlocked 窗口；当前 sentinel 只训练 `256` 个窗口、验证/校准各 `128` 个窗口，模型为 hidden=32、history=8、horizon=20、8 epochs。
2. 完整 RSSM v3 和 node-x-safe 两次正式训练的 validation loss 到 epoch 8 都仍持续下降，未显示收敛平台；独立 R4 路径的最佳轮次为 epoch 22。8 epoch sentinel 能检查短预算可训练性，不能独立判定完整 RSSM 的充分性能。
3. runner 按单一 aggregate validation loss 选 checkpoint，而 P4 最终按 link-F1、node-x MAE ratio、throughput、RB occupancy 和 task delay多个门分别判定。训练选择目标与验收目标不一致。
4. 位置任务的正式输入只有 `x/y/z/speed/acceleration/cpu/storage`，动作只有卸载、RB、返回和 CPU 分配；没有 heading、速度向量、路线或机动控制。8 帧历史可推断已有方向，但不能直接给出未来转向意图。该项是信息充分性风险，尚未由分段上界审计定量证明。
5. link activity 在训练 split 中 positive=`16269`、negative=`1755657`，正例约占 `0.918%`。F1 对阈值和少数正例排序非常敏感；已有只读诊断也显示 h1/h20 召回塌陷。
6. 完整 RSSM v3 中 formal base 的 node-x ratio=`1.15756`，RSSM correction 使完整输出变为 `1.28774`；node-x-safe 把 correction 从 `3.04245 m` 压到 `0.07621 m`，但从头联合训练后的 base ratio 又恶化为 `1.51660`。这证明局部约束会通过共同训练改变其他参数轨迹，不能继续把问题当成单一 correction 幅度问题。
7. 历史上节点类型、RB 指标、递推状态、规则反馈、概率语义及完整 RSSM decoder/初始化合同曾先后补齐。相关重跑中有一部分是为了使证据有效，但两次完整 RSSM GPU run 本应由更早的 pre-GPU 一致性审计拦截。

## 对此前推进方式的判断

- 有价值且必须保留：canonical h20 数据合同、双图与规则层、无未来标签泄漏、strict reload、manifest、完整 RSSM prior/posterior/teacher 语义、persistence 基线和 locked-test 封存。
- 可避免的重复：把 CPU micro 可运行误当作性能风险已降低；围绕最新失败指标逐项加补丁；在没有先检查输入信息、目标冲突和训练是否收敛时启动新 sentinel；让同一个 P4 同时承载合同修复、方法补全、概率校准和正式性能结论。
- 因此，`冻结 v3 base、只训练 correction` 暂不作为下一训练。它只是候选假设，不能回答信息不足、目标冲突或预算不足。

## 单一下一动作

只用现有 unlocked 数据与 checkpoint，完成一次 CPU-only 的“信息充分性与目标冲突审计”，不训练新模型：

1. 按直行/转向片段分解 h1/h5/h10/h20 位置误差，量化没有未来机动意图时的可预测边界；如需使用未来 heading/路线，只能作为 oracle 上界，不能成为部署输入或性能结果。
2. 在冻结 batch 上计算 node-x、link activity、task/运营目标对共享参数的梯度方向关系，判断是否存在稳定的目标冲突。
3. 对现有 checkpoint/训练曲线核对 aggregate validation loss 与五项正式门的排序是否一致，并判定 8 epoch/256 窗口是否只够做执行 sentinel。

审计后只允许三选一：信息不足则先修订合法状态输入；目标冲突则拆分或分阶段训练物理与信息分支；预算/选择门不一致则先修订 sentinel 与 checkpoint 选择合同。审计前不再增加 loss、head、阈值或 seed。

## 边界

P4 继续 blocked；当前 GPU 不需要，可关闭。`locked_test` 保持未访问，其他 seed 和独立概率门不开放，`formal_performance_claim_ready=false`。
