# P4 edge GRU接口只读追踪设计

状态：已复核、已实施、已完成唯一一次CPU trace；机器判定=`incoming_readout_below_threshold_dominant`，P4仍blocked
日期：2026-09-05
当前主线：P4 blocked

## 1. 第一性原理问题

链路活动头的输出只由当前物理边hidden state决定：

```text
raw_logit = link_activity_head(edge_hidden)
```

物理边每一步的状态变化为：

```text
edge_hidden_after = edge_transition(edge_input_message, edge_hidden_before)
```

上一次“完全旁路edge GRU”的干预使全部链路分数低于冻结阈值，说明`edge_transition`是产生高分所必需的，但没有回答低分是在进入GRU前已经形成，还是由这一次GRU更新压低。

本设计只回答：

> 对当前5855个真实正样本漏报，更新前的edge hidden在同一个link head下是否已经低于阈值；还是更新前高于阈值、经过GRU后才跌破阈值？

## 2. 不采用的路线

- 不继续旁路或清零CFE消息；这会开启第二个模块干预。
- 不关闭rule feedback；h1本来就没有上一预测步反馈，而且该动作会形成第三条实验路线。
- 不加入persistence捷径、不改link head、不改loss；这会直接进入修复，跳过原因定位。
- 不做阈值扫描或概率校准；冻结raw threshold仍为`0.9`。

## 4. 唯一观察方法

给`FormalDualGraphWorldModel.edge_transition`注册只读forward hook。hook只复制以下张量，不修改或替换output：

```text
edge_input_message
edge_hidden_before
edge_hidden_after
```

对每一步使用checkpoint中的同一个`link_activity_head`计算：

```text
pre_update_logit  = link_activity_head(edge_hidden_before)
post_update_logit = link_activity_head(edge_hidden_after)
```

`post_update_logit`必须与模型正式输出`link_activity_logits`逐元素一致；否则停止。hook命中次数必须为`20 * validation_batch_count = 1280`，退出后必须完全移除。

为了证明观察的是GRU真实计算，而不是错误的hook位置，按PyTorch GRUCell固定方程，用同一权重重算reset gate、update gate、candidate state和hidden output；重算output与真实output最大绝对误差必须不超过`1e-6`。gate只作为解释字段，不作为修复结论。

## 5. 统计对象

只围绕低召回主线统计真实正样本，不扩展到新性能实验。对overall、h1至h20及h1/h5/h10/h20重点项，分别报告：

- all positive；
- continued active；
- newly active；
- previous unobserved。

每组将样本分成四种更新状态：

```text
pre_positive  -> post_positive
pre_positive  -> post_negative
pre_negative  -> post_positive
pre_negative  -> post_negative
```

其中`post_negative`且label为正就是原始FN。对FN额外报告：

- 更新前已经低于阈值的数量和比例；
- 经过本次更新才从高于阈值跌到低于阈值的数量和比例；
- pre/post raw logit与delta logit的q0/q10/q50/q90/q100；
- update gate先对每个有效物理边的hidden维取算术均值，再报告这些“逐边均值”的q0/q10/q50/q90/q100；明确它只是内部状态摘要。

## 6. 预注册机器判定

定义：

```text
incoming_below_fraction
= count(pre_negative -> post_negative among positive labels)
  / count(post_negative among positive labels)

downcross_fraction
= count(pre_positive -> post_negative among positive labels)
  / count(post_negative among positive labels)
```

三种判定互斥：

1. 若overall、h1、h20的`incoming_below_fraction`均不低于`0.80`：

```text
edge_gru_interface_trace = incoming_readout_below_threshold_dominant
```

2. 否则，若overall、h1、h20的`downcross_fraction`均不低于`0.80`：

```text
edge_gru_interface_trace = transition_downcrossing_dominant
```

3. 其余情况：

```text
edge_gru_interface_trace = mixed_no_single_dominant_pattern
```

`0.80`表示同一机制至少覆盖五分之四的漏报，避免用微弱多数宣称主要原因。不得在看到结果后修改该比例。

## 7. 结论边界

- `incoming_readout_below_threshold_dominant`只说明：在正式link head的读取方向上，状态进入本步GRU前已经主要低于阈值；不等于latent中完全没有活动信息。
- `transition_downcrossing_dominant`只说明：主要FN由本步GRU产生向下跨阈值；仍不能直接决定是GRU gate还是输入消息造成。
- `mixed_no_single_dominant_pattern`表示没有单一接口位置覆盖主要漏报，当前路线继续blocked。
- 三种结果都不自动授权模型修改、训练或第二个干预。Sol必须读取原始报告，再向用户提交一个唯一下一动作。
