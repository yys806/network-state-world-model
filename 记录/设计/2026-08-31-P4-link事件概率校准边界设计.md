# P4 Link 事件概率校准边界设计

更新时间：2026-08-31

状态：`approved and frozen for implementation`

## 1. 结论与适用边界

本设计采用方案 B：`positive-weight analytic inversion + scalar temperature scaling`。

它解决的唯一问题是：当前 link head 使用 `pos_weight=50.0` 的 weighted BCE 训练，正式 runner 却把 `sigmoid(raw_logit)` 直接当作链路活动事件概率。方案 B 在模型冻结后建立一个可审计的概率边界，使 raw weighted score、正式事件概率、概率阈值和分类决策各有唯一含义。

本设计不会自动关闭整个 P4。它能关闭 `protocol_theory_mismatch`，并保护方案 A、checkpoint、sample IDs、mask、现有分类决策和 No-Go 结论；但当前 validation link-F1 仍低于 persistence，P4 性能门仍需在本设计通过后另行定位。不得把概率语义修复表述为性能通过。

## 2. 冻结项与非目标

以下内容全部冻结：

- train/validation/calibration=`256/128/128`；

## 3. 数学定义

令 link head 的原始 logit 为 `z`，训练正类权重为 `w=50.0`。

### 3.1 原始加权分数

```text
s = sigmoid(z)
```

`s` 的正式字段名为 `raw_weighted_score`。它保留 weighted BCE 的类别代价偏移，只能称为原始加权分数，不能称为已经校准的事件概率。

### 3.2 固定解析反演

```text
u = z - log(w)
p_inverse = sigmoid(u)
          = s / (w - (w - 1)s)
```

`u` 为去除理论类别权重赔率偏移后的 logit。该步骤没有可学习参数，也不使用 validation 或 calibration 标签；它必须与现有 `correct_positive_weighted_probability` 数值等价。

### 3.3 唯一可拟合参数

```text
p_event = sigmoid(u / T),  T > 0
```

`p_event` 是正式 `event_probability`。`T` 是本组件唯一可拟合参数。

`T` 只使用 calibration split 上同一有效 physical-edge 与 `aggregate_link_activity_mask` 拟合，目标为未加权 Bernoulli NLL。令 `V_cal` 为 calibration split 中 `physical_edge_endpoint_index` 有效且 `aggregate_link_activity_mask=true` 的全部元素，拟合目标固定为：

```text
L(q) = mean_{i in V_cal} BCEWithLogits(u_i / exp(q), y_i)
```

拟合不传入 `pos_weight`，reduction 等价于对 `V_cal` 的普通算术均值。实现以 `q=log(T)` 为唯一参数，使用 CPU float64、全量 calibration 向量和 PyTorch LBFGS 确定性求解；`q` 初始值固定为 `0`，`max_iter=100`、`tolerance_grad=1e-12`、`tolerance_change=1e-12`、`line_search_fn='strong_wolfe'`。拟合后若 `T` 非有限或不大于零，校准门直接失败，不回退到另一个方案。

identity-temperature 判定固定为 `abs(q)<=1e-12`；满足时记录 `T=1.0`，否则必须按实际 `T=exp(q)` 记录，不得把接近 1 的温度改写为 1。`T=1.0` 是方案 B 的合法结果，表示固定解析反演已经足够，不能为了制造“改善”再增加参数。

## 4. 阈值和决策等价性

不得在概率域重新使用数值 `0.1/0.3/0.5/0.7/0.9`。每个既有 raw threshold `r` 必须通过同一单调函数映射：

```text
tau(r) = sigmoid((logit(r) - log(w)) / T)
```

正式决策为：

```text
legacy_decision = 1[s >= r]
probability_decision = 1[p_event >= tau(r)]
```

对全部有效样本和五个候选，二者必须逐元素完全相同。阈值选择必须先在 legacy raw threshold 候选 `r` 中完全复用现有规则：

```text
argmax_r (calibration_F1(r), -abs(r - 0.5))
```

只有得到 raw candidate identity `r*` 后，才能输出正式 probability threshold `tau(r*)`；严禁在 `tau(r)` 的概率坐标上重新使用“距 0.5 更近”的 tie-break。当前选中的 candidate identity 必须仍是 legacy raw `0.9`，validation 只应用该选择。TP、FP、FN、precision、recall、F1 和 AUPRC 不得因本设计改变。

这意味着当前 sentinel 的正式 F1=`0.3724`、persistence=`0.5901` 和 `no_go` 必须原样保留；不得用校准结果重写或覆盖原报告。

## 6. 概率指标

概率质量只对 `event_probability` 计算，不能对 `raw_weighted_score` 计算后仍称为正式概率指标。

必须报告：

- unweighted Bernoulli NLL；
- Brier score；
- ECE；
- calibration fit-split 值和 validation 泛化值分开；
- overall 以及 `k=1/5/10/20`。

ECE 固定使用 `[0,1]` 上 15 个等宽区间：第 `j` 个区间为 `[j/15, (j+1)/15)`，`j=0,...,13`；最后一个区间为 `[14/15, 1]`。空区间忽略，按有效样本数加权每个区间的 `|mean_probability - empirical_frequency|`。NLL 仅在数值计算边界将概率截到 `[1e-7, 1-1e-7]`，artifact 仍保存截断前概率范围检查。

F1、precision、recall 使用 mapped probability threshold；AUPRC 使用 `event_probability` 排序。由于变换严格单调，这些分类/排序指标必须与 legacy raw-score 结果一致。

## 7. CPU-only 验收门

实现阶段必须按 TDD 执行：先加入能够在旧正式路径上失败的测试并观察 RED，再写最小实现。

最低验收项：

1. 解析反演与 `sigmoid(z-log(w))` 数值等价；
2. `T=1` 时结果等于解析反演；
3. `T>0` 且映射严格单调；
4. 五个阈值的 legacy/probability decision 逐元素完全等价；
5. calibration 是唯一拟合和阈值选择 split，validation 使用标志始终为 false；
6. 同一 mask counts、sample IDs、checkpoint 和 tensor provenance 未漂移；
7. validation 的 TP/FP/FN/F1 与 sentinel 逐项不变；
8. calibration NLL 不高于 `T=1` 解析反演基线，validation NLL、Brier、ECE 相对同一基线均不恶化；允许最优 `T=1`，不强制制造改善；
9. checkpoint strict reload，missing/unexpected keys=`0/0`；
10. 新 artifact manifest 无缺失或哈希不一致；
11. `gpu_execution=false`、`locked_test_accessed=false`、`formal_performance_claim_ready=false`。

任一项失败即停止，不修改 loss、模型、阈值网格或拟合第二个 calibrator，不通过 validation 选择补救路线。

## 8. 错误处理

以下情况必须显式报错并停止：

- `pos_weight<=0`、来源不是 train-only 或与冻结 SHA-256 不同；
- raw logit、温度或输出概率非有限；
- `T<=0`；
- mask 数量、sample IDs 或 checkpoint 身份漂移；
- mapped threshold 不在 `(0,1)`；
- legacy/probability decisions 不等价；
- validation 被用于拟合、选择温度、选择方案或产生新阈值；
- 任何 `locked_test` 访问迹象。

不得静默使用默认 `T=1`、默认 `pos_weight`、顶层默认 threshold=`0.5` 或 validation 最优 raw `0.7` 作为回退。

## 9. 与 P4 完成的关系

方案 B 通过后，可关闭的是“link score/probability/threshold/metric 语义不一致”子门，并保留全部已验证成果，因而不会因这次修复返工方案 A、tensor 或 sentinel。

它不会关闭当前 link-F1 性能失败。因为 mapped threshold 刻意保持原决策，P4 在该设计通过后仍应记录为：

```text
probability semantics gate = passed
sentinel performance gate = no_go
P4 = blocked
```

下一轮若继续处理性能，只能基于校准后已闭合的概率证据再定位一个新的、经用户批准的单变量原因；不得在本设计内夹带性能修复。这样可以避免理论、实现和结果再次分叉，也避免重复现有实验。
