# P4 物理边规则反馈进入 GRU 输入设计

日期：2026-08-30
状态：方案 A 的 Task 6 TDD、单点代码修改和 CPU 极小接口 smoke 已通过；尚未进行正式性能训练。

## 1. 问题与证据

当前 `FormalDualGraphWorldModel.forward` 在第 2 步起先执行：

```python
edge = edge + self.state_feedback["physical_edge"](rule_feedback["physical_edge"])
```

随后才计算图消息并调用：

```python
edge = self._apply_transition(self.edge_transition, edge_message, edge)
```

因此规则层的 physical-edge correction projection 会先直接改变 recurrent hidden state。冻结 checkpoint 的单变量干预证明：只把这条 projection 临时置零，seed `20260831` validation 的 h20 去 bias FP 从 `1086` 降到 `0`，pre-bias q99 从 `4.96` 降到 `-0.16`，h1 完全不变。报告 SHA-256=`6b89049612e97bcb50ad929662423f17630f5a220a6ac78b4bd31ee8f5ea1f2e`。

该证据证明 direct physical-edge feedback 路径足以产生长步高分尾部，但不支持永久关闭反馈。项目理论要求规则修正后的最终状态进入下一步；同时，现有干预没有证明正样本、状态、任务和运营指标在关闭反馈后仍受保护。

## 2. 唯一修改

保留原 `state_feedback["physical_edge"]` 线性投影及其参数，只改变它进入 edge GRU 的位置：

```python
edge_rule_feedback_message = torch.zeros_like(edge)
if rule_feedback is not None:
    edge_rule_feedback_message = self.state_feedback["physical_edge"](
        rule_feedback["physical_edge"]
    )

# physical_message_pass 和 cross-flow coupling 仍按原逻辑生成 edge_message
edge = self._apply_transition(
    self.edge_transition,
    edge_message + edge_rule_feedback_message,
    edge,
)
```

删除的唯一行为是：不再执行 `edge = edge + projected_correction`。node、flow、task feedback 仍保持现状；规则层显式状态、`recursive_states`、edge GRU、图消息、cross-flow coupling、link head、参数形状、checkpoint keys、tensor、loss、class weights 和 calibration-only threshold 全部不变。

## 3. 理论口径

规则修正是本步 transition 的外部输入，不是上一时刻 recurrent hidden state 本身。将 projection 放入 GRU input message 后，修正信息仍进入下一步，但由同一个 GRU transition 统一处理；这与“修正后的最终状态反馈下一步”的项目定义一致，也避免在进入 transition 前直接改写 hidden state。

该改动只能称为 `physical-edge rule-feedback input routing fix` 候选，不是新模型、完整 RSSM 或最终方法。CPU smoke 只证明接口、梯度、保存和 reload；正式性能必须重新训练后由固定门判断。

## 4. 验收与停止条件

1. RED 测试必须在旧实现上证明：第二步 edge GRU hidden 被 direct feedback 预先改变。
2. GREEN 后第二步 edge GRU hidden 在“正常反馈”和“临时置零反馈”两次 forward 中必须相同；两次 GRU input 的差必须等于捕获的 projected physical-edge correction。
3. h1 不得变化；projection 必须非零，避免空测试。
4. `state_dict` 参数名和形状不得变化，现有 checkpoint 必须 strict load。
5. 规则层、世界模型、loss、metrics、gate 和两个诊断脚本的相关测试必须通过。
6. CPU 只运行 `train/validation/calibration=2/1/1`、1 epoch 的 isolated smoke；不把数值当性能结果。
7. 任一测试、strict reload、manifest 或边界字段失败即停止，不叠加第二个修改。
8. `locked_test_accessed=false`；CPU smoke 通过后如需收敛性能训练，先向用户申请开启 GPU。
