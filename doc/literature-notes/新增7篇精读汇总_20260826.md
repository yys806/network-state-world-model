## 二、对 PI-JWM 最有价值的三条线索

### 1. 把“世界模型是否可信”拆成可验证链

WorldSimProbe 的核心不是更复杂的模型，而是明确 simulator contract：动作是否被正确实现，环境变化是否由该实现的动作和接触支持。对 PI-JWM，建议把每个 rollout step 记录为：`future_action` → `action_source/合法性` → `deterministic_rule_update` → `learned_service_outcome` → `next_state/task_transition` → `constraint_residual`。这能把当前的规则守恒回放和未来的候选动作规划接到同一条证据链上。

### 2. 候选动作规划必须是真正的逐候选反事实闭环

WONDER 展示了完整结构：从同一上下文生成合法候选，逐候选调用 world model，得到候选未来指标，选择一条，提交后更新上下文并重新评估。RMWorld 则补充了可信度、互补性、决策边界和 rollout 预算。两篇合起来，直接支持当前审计结论：现有 direct belief/state scorer 不能改名为 planner；下一步应先补齐机制和机器可查 artifact，再谈 GPU planner 实验。

### 3. 物理先验与学习动态要分工

RFWM、Khora 都采用“确定性/物理结构先给出可解释部分，学习残差补充复杂部分”的思想；这与 PI-JWM 已闭合的 deterministic rule layer 方向一致。但类比只能作为设计启发，具体字段仍须遵守 frozen tensor contract、train-only statistics、mask 和 DAG/flow conservation。EMWM 则提醒：多模态输入必须保留缺失语义，不能把 zero padding 当作真实观测。

## 三、建议的后续顺序

1. 先把本批次启发转成一个 planner mechanism audit fixture：候选生成、共享初始状态、逐候选 action injection、未来 state/task/cost/risk、选择和 replanning 都必须可追踪；这一步 CPU、非 locked-test。
2. 再做 task-weighted/decision-boundary 诊断和 action perturbation contract，保留原始状态误差，不用代理量覆盖它。
3. 只有机制审计通过、理论-代码-数据-指标一致后，才决定是否实现候选动作 planner 并重新走 CPU gate、GPU smoke、多种子非锁定训练；locked-test 和最终性能声明仍关闭。
