# PI-JWM 项目治理与重构设计

日期：2026-07-11

## 1. 目标

在不破坏 PI-JWM 研究证据链和可复现性的前提下，完成项目结构治理、代码审计、依赖补全、文档修复和冗余文件清理，使后续工作能够围绕“世界模型主干 + 自主动作策略 + 冻结世界模型评估”稳定推进。

本次治理采用平衡策略：可再生成缓存直接删除；可能仍有研究价值但不属于当前主线的内容移入项目外隔离区；冻结基线、当前候选、关键数据、模型权重和实验指标保留在项目内。

## 2. 范围与边界

治理范围：

- 根目录的项目说明、Git 配置、依赖配置和计划文件。
- `代码/src/pi_jwm/`、`代码/scripts/`、`代码/tests/`。
- `代码/artifacts/` 中的数据集、模型、实验、报告和打包文件。
- `文档/` 中的项目说明、研究进展、组会材料、论文和历史归档。
- `代码/reference/AirFogSim/` 的边界、依赖和本地缓存，但不重写第三方实现。

补充授权的先行清理：

- `数据集构建任务/WaveFarer资料/` 整体移入项目外隔离区。
- `数据集构建任务/` 根目录下三份任务 DOCX 保留。

明确不治理：

- 用户未授权的外部服务器、远程实验目录和外部数据。

研究命名保持不变：主框架是 PI-JWM；AirFogSim 只是参考仿真器和数据来源；当前决策方法仍标记为 `v11 candidate`，不命名为 v12 或最终 v11。

## 4. 代码与研究思路审计

### 4.1 数据链

逐项验证：

- seed 切分发生在归一化统计之前，统计量只能使用训练 seed。
- 限制样本数时，不得使用受限子集重新估计全局归一化统计。
- `edge_a_future` 的生成必须有来源日志、非零率和核心匹配率保护。
- `future_action_mode=full`、`first_step_only`、`none` 的语义在训练与评估中一致。
- 数据集摘要、节点词表、边词表和 NPZ 张量形状彼此一致。
- active-rate 极端稀疏性必须在损失、采样、指标和模型选择中显式处理。

### 4.2 世界模型

检查双图消息传递是否真正使用物理边、信息边和端点节点，而不是只做同形张量融合；检查 rollout 每一步的状态更新、未来动作条件、任务状态更新和输出头是否一致。

真实未来动作条件下的结果只用于世界模型能力和上界参考。所有“自主”结果必须由测试时可用的状态生成动作，不能使用真实未来标签、测试集拟合、测试集阈值选择或测试集候选选择。

### 4.3 动作策略与 bridge

重点检查：

- 行为克隆的活动支持集与动作幅值是否分开评价。
- RB/CPU count-total 等耦合结构是否在编码、解码和 bridge 中保持一致。
- codebook、prototype、calibrator 和 selector 只能用训练集或明确的验证集拟合。
- 验证集用于模型和 operating point 选择；测试集只做一次匹配评估。
- sample oracle、true-future 和 test-best 只能标为诊断上界，不能混入 deployable 结果。
- actual-rollout selector 的训练标签、特征和最终 frozen-world-model 评价使用同一 rollout 口径。

### 4.4 指标与结论

主要指标保持 active-rate RMSE，同时强制报告 activity precision、recall、F1、full-link RMSE、node RMSE 和 task RMSE。任何候选晋级必须同时给出验证选择规则、匹配测试结果、样本规模、seed 和输出路径。

代码中发现的逻辑问题按测试驱动方式修复：先新增能够复现问题的失败测试，再修改实现，最后运行相关测试和完整测试套件。

## 5. 文件治理规则

### 5.1 直接删除

仅限明确可再生成且不含研究证据的内容：

- `__pycache__/`、`*.pyc`。
- 已失效的 `*.pid`。
- 空目录。
- 临时编辑器文件和明确的零字节临时文件。

### 5.2 移入项目外隔离区

- 重复压缩包和内容完全重复的 PPT/PDF/导出文件。
- 已被正式实验替代的 CPU smoke、失败 probe 和中间 checkpoint。
- 仅包含控制台输出、且已有结构化 JSON/CSV 摘要的运行日志。
- 历史生成器工程、中间导出和旧版汇报副本。
- 未被代码默认路径、计划、报告、论文或证据索引引用的旧实验目录。

隔离区位于 `D:\shen\网络组_隔离备份\2026-07-11_PI-JWM治理\`。每个移动项记录原路径、隔离路径、文件大小、SHA256、治理原因和恢复命令。目录移动前先生成清单，移动后验证文件数与总字节数。

### 5.3 项目内保留

- 当前主数据集及其词表、摘要和完整性证据。
- v6-v9 中承担基线或关键消融证据的最小实验集合。
- 冻结 v10 包、checkpoint、哈希清单和 action ablation 证据。
- 当前 v11 candidate 的实现、测试、严格评估产物和最新证据索引。
- 论文、研究进展总览、当前组会材料和必要文献。
- 第三方 AirFogSim 源码，但移除其本地虚拟环境和缓存。

## 6. 文档和依赖治理

- 重写根 README，使其反映当前 v11 candidate 状态、主要入口、环境安装、测试命令和结果边界。
- 保留原始乱码计划到隔离区，重建简洁的 `本地计划表.md`；历史细节由实验摘要和归档文档承担。
- 增加 `pyproject.toml`，声明支持的 Python 版本、核心依赖、可选实验依赖和 unittest 入口。
- 更新 `.gitignore`，隔离 checkpoint、日志、缓存、虚拟环境和大体积再生数据，同时不隐藏需要保留的结构化证据。
- 生成实验保留索引和脚本迁移映射，避免路径调整后找不到历史入口。

## 7. 执行顺序与回滚

1. 建立隔离区和只读清单，不移动文件。
2. 建立基线验证：完整测试、关键数据完整性检查和主入口 smoke。
3. 补齐项目配置、依赖和文档，保持兼容路径。
4. 审计并修复数据、世界模型、策略和 bridge 的逻辑问题。
5. 下沉高复用脚本逻辑，每次只处理一个明确边界。
6. 清除直接可再生成内容。
7. 按保留索引将重复和非主线内容移入隔离区。
8. 再次运行完整测试、数据校验和关键 smoke。
9. 输出最终文件树、保留/隔离清单、恢复说明和后续研究入口。

任何批次失败时，停止后续清理；代码通过 Git 分支回滚，隔离文件按清单恢复到原路径。隔离备份在用户确认前不永久删除。
