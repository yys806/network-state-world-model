# PI-JWM R6 学习策略 CPU 预检结果

日期：2026-08-08

## 1. 本阶段回答的问题

本阶段只验证：冻结的 PI-JWM 世界模型能否向独立策略器提供显式状态和隐式状态，学习策略能否在统一动作契约下生成候选动作，动作能否经过安全投影变成可执行动作，以及 Actor–Critic 与 PPO 式目标能否在 CPU 上完成一次有限、可复现的参数更新。

本阶段不回答策略性能优劣，不启动 GPU，不访问 locked-test，不修改世界模型参数，也不冻结最终方法。AirFogSim仍只作为既有数据与后续动作执行环境，不是PI-JWM框架本身。

## 2. 已实现并固定的接口

| 模块 | 已固定内容 | 验证结果 |
| --- | --- | --- |
| `PolicyState` | 输入由当前显式状态、冻结世界模型隐式latent、动作mask、逐节点CPU容量、逐任务执行节点映射及样本身份组成；进入策略器前全部`detach`；拒绝未来target和locked-test | 通过 |
| `ActionSpec` | 固定卸载、RB和逐任务CPU动作槽位及安全no-op索引 | 通过 |
| `MaskedActorCritic` | 共享状态编码器，分别输出卸载/RB离散分布、CPU连续分布和状态价值；非法离散动作概率严格为0 | 通过 |
| `SafetyProjector` | 依次检查有限值、实体mask、离散动作合法性、CPU非负性及逐节点容量；每次修正保留原因和投影前后数值 | 通过 |
| Actor–Critic/PPO更新 | 使用同一策略网络和动作分布，完成有限loss、有限梯度和策略参数变化检查 | 通过 |
| 冻结世界模型隔离 | 策略状态由R5.1冻结候选B的checkpoint生成；策略更新前后逐参数SHA-256一致 | 通过 |

## 3. 正式真实状态预检

正式预检没有使用只为测试构造的随机图状态，而是绑定以下既有冻结资产：

- 数据：`代码/artifacts/datasets/airfogsim_teacher_aligned_v3/`；
- 评价协议：`代码/artifacts/evaluation/pi_jwm_eval_protocol_v3/`；
- 世界模型：R5候选B、训练seed `20260803`的冻结checkpoint；
- 候选角色：R5.1正式冻结文件；
- 执行协议：R6 CPU同场景配对闭环正式bundle。

从非锁定validation窗口`load_high__density_dense__r07`、环境seed `507`、时隙`298`构造策略状态。该状态包含24维显式摘要、32维Graph-RSSM belief、481个任务槽位、44个CPU节点槽位，其中435个CPU任务和38个CPU节点处于活动状态。策略只读取历史观测、历史动作和当前mask；未来target未进入策略输入。

由于本轮只验收CPU学习接口，卸载和RB动作在正式状态中被限定为安全no-op。这样可以验证连续CPU策略、逐节点容量和梯度链，而不会在尚未冻结RB可用域及联合动作执行协议时伪造可行动作。通用模块已经支持卸载/RB mask，但其正式学习训练仍未通过入口门。

## 5. 实施中发现并修复的问题

前三次正式命令都在写出正式bundle之前失败，输出目录均不存在，因此没有把失败结果与最终产物拼接。

| 次序 | 真实问题 | 根因 | 修复与回归证据 |
| --- | --- | --- | --- |
| 1 | Graph-RSSM belief读取失败 | 误按R3确定性latent的`.joint`接口读取R5 Graph-RSSM belief；后者实际由deterministic与stochastic两部分组成 | 增加两类belief分支和定向测试；Graph-RSSM策略latent固定为两部分拼接 |
| 2 | 正式状态构造出现`PolicyIdentity`未定义 | 预检模块漏导入已有契约类型 | 补充真实资产集成测试并修复导入 |
| 3 | CPU投影后被判定超容量 | `float32`按比例缩放后，两个节点分别残留约`7.15e-7`和`2.38e-7`的舍入超量；节点映射和投影公式本身正确 | 增加真实边界回归用例；缩放后从最大分配项回收舍入残差，严格保证逐节点和不超过容量 |
| 4 | 外部训练批次可把被mask的离散动作送入`evaluate()` | 采样路径不会选中非法动作，但评价路径只检查索引范围，没有再次检查当前状态mask | 收尾审查新增失败测试；现在按effective mask拒绝非法卸载/RB动作，防止经验回放静默产生极大有限负log-prob |

最终R6新增22项测试、既有R6回归17项和历史双图/active-rate回归75项全部通过。

## 6. 阶段结论与下一步门槛

当前可固定：`r6_learning_policy_cpu_ready=true`。这表示学习策略的软件契约、真实状态入口、CPU数值更新、安全投影和世界模型隔离已经具备。

当前必须保持：`r6_gpu_strategy_training_ready=false`、`final_method_frozen=false`。进入GPU前还需单独冻结正式reward/多目标标量化与约束处理、联合动作训练范围、rollout/GAE样本生成、更新预算与停止条件、训练seed、checkpoint与失败保留规则，以及同四个CPU策略臂的闭环配对评价矩阵。卸载/RB若要进入学习训练，还必须先从正式执行环境构造真实可行mask和动作结果，不得沿用本轮CPU门的no-op占位。
