# PI-JWM R6 在线闭环 GPU 训练前预检结果

日期：2026-08-08

## 结论

本地 CPU 门禁与服务器 GPU 启动门均已通过。2026-08-09已完成2k CUDA smoke和18-run并发启动验证，正式`10k×18`第一阶段已启动；当前结论为`formal_gpu_training_started=true`，不是训练完成或方法定型。只有该阶段全部run、学习曲线和validation门通过，才从同一检查点续到100k。

旧版预检曾把“AirFogSim 实际 reward＋冻结教师状态”称为真实闭环。复核发现，策略动作偏离默认轨迹后，冻结教师张量不再代表当前环境，因此旧版结论只能证明动作与 reward 接口可执行，不能证明状态闭环；本文件以在线重采集结果替代该表述。

## 修正后的闭环

每个决策步执行以下固定流程：候选生成与合法性过滤；策略选择卸载/RB/CPU联合动作；AirFogSim执行动作；重新采集物理节点、信息通信边、任务/DAG、传输事件和实际动作；依据`PIJWM-DG-Contract-v3`形成最近8步显式状态；冻结Graph-RSSM从该在线状态生成隐式belief；AirFogSim实际反馈生成reward；Actor–Critic或PPO更新策略器。冻结教师轨迹只提供张量容量、归一化统计和协议绑定，不提供动作分叉后的状态值；世界模型始终`eval()`、`stop-gradient`且参数哈希不变。

反事实reward代理没有进入正式路线。54条非锁定教师轨迹提供16,200个默认动作事实样本，但`deadline_first`、`priority_first`、`load_balance`、`rate_aware`和`energy_conservative`均没有反事实结果标签，因此不能训练六候选reward代理。正式训练改为读取AirFogSim真实执行反馈，不制造伪标签。

## 本地证据

| 检查 | 结果 |
| --- | --- |
| 两种目标×三种状态 | Actor–Critic/PPO与显式、隐式、联合状态共6组均完成真实更新 |
| 动作分叉 | 每组2步均执行非默认候选；32步长闭环覆盖全部6类候选 |
| 在线状态 | 六组均得到2个不同显式状态哈希；长闭环32步得到32个不同状态 |
| 真实事件 | 长闭环记录4条CPU动作、6条卸载、12条RB、6条回传和12个传输事件 |
| 优化 | 32步完成4次更新，每次梯度非零且参数变化 |
| 安全 | 六组和32步闭环硬约束违规均为0 |
| 确定性 | 两次同seed 32步运行的候选计数和4次`total_loss`完全一致 |
| 续训 | 同一run先训练2步，再由原子检查点续到4步，优化器和计数连续 |
| 选模 | validation-only评价可执行、候选checkpoint eligible且best checkpoint已写入 |
| 边界 | 生成证据未读取locked-test；世界模型未更新；checkpoint重载逐参数一致 |

本地32步实测训练主体耗时约7.76秒，即0.242秒/环境步。服务器2k CUDA smoke实测659.94秒，即0.330秒/环境步，显存约488 MiB。服务器容器CPU配额为16核，而PyTorch默认每进程64线程；未限线程的双并发恶化到约2.42秒/步。将worker限制为4线程后，双并发恢复到0.153—0.178秒/步；最终4并发×2线程的18-run×128步完整启动门耗时140秒，18/18完成、失败0。因此正式矩阵固定4并发、每worker 2线程，不再使用原先未经服务器验证的6并发估计。

## 服务器GPU启动记录（2026-08-09）

2k CUDA smoke使用`actor_critic__explicit_latent__seed_20260803`，完成2000步和16次更新；六类候选选择计数均大于0，非默认选择1635次，显式状态哈希2000个，硬违规0，在线CPU/卸载/RB/回传/传输事件均非空，checkpoint重载通过，`device=cuda`、`world_model_updated=false`、`locked_test_accessed=false`。

首次正式6并发启动保留在`pi_jwm_r6_gpu_training_v2`。它准确暴露AirFogSim示例配置固定使用TraCI端口8813，只有一个SUMO实例能连接，其余run以`Address already in use/FatalTraCIError`失败；该批次立即停止，失败日志不删除、不混入成功结果。修复仅发生在PI-JWM runner/launcher层：18个run获得互异端口，端口写入命令与manifest；AirFogSim第三方源码和实验语义未改。端口与worker线程限制新增测试先失败后通过，本地R6测试为75/75通过，服务器原有72项扩展后回归与专项测试均通过。

修复后4并发×2线程、端口18900—18917的18-run×128步端到端启动门18/18完成、失败0，单run平均20.45秒，墙钟140秒，无TraCI/端口/Traceback错误。正式输出改用新目录`代码/artifacts/formal_training/pi_jwm_r6_gpu_training_v3/`，固定4并发、每worker 2线程、端口18813—18830和每run 10,000步；失败`v2`继续保留。正式矩阵尚在运行，当前不得报告策略性能或续到100k。

10k阶段首批run达到10000步后，在原子续训检查点写入前统一暴露尾批边界错误：`10000 mod 128 = 16`，最后16条transition小于minibatch 32，旧runner未执行尾批更新并以`resume checkpoint requires rollout_length >= minibatch_size`拒绝保存。该问题不影响此前训练内容：失败run最近的完整原子checkpoint均位于9984步，失败日志和10000步progress原样保留。矩阵发现错误后立即停止；修复只在到达目标步数且存在非空尾批时执行一次尾批更新，常规128步rollout、reward、模型、数据、seed和评价协议均不改变。新增回归先失败后通过，本地和服务器R6测试均为75/75。`actor_critic__explicit_only__seed_20260803`已从9984步补跑16步并完成12条validation轨迹、768个验证步：最终10000步、79次更新、按时完成率1.0、平均时延0.490805、硬约束违规0、checkpoint重载一致、世界模型未更新、locked-test未访问。矩阵现按原协议从各run最近checkpoint恢复；该单run结果只证明修复和恢复链正确，不作为方法性能结论。

恢复后的10k矩阵已全部结束。机器汇总为`expected_count=18`、`complete_count=18`、`failed_count=0`；18个唯一run覆盖`{Actor–Critic, PPO} × {explicit_only, latent_only, explicit_latent} × 3 seeds`，每组均为10000环境步、79次策略更新和1份validation报告，硬约束违规0、checkpoint重载一致、世界模型未更新、locked-test未访问，所有记录中的loss、entropy和gradient norm均为有限值。服务器调度器与worker已全部退出，GPU无计算进程。完整目录165个文件、4,857,190字节已下载到`代码/artifacts/formal_training/pi_jwm_r6_gpu_training_v3/`，服务器—本地逐文件SHA-256校验0失败。`formal_budget_complete=false`仅表示冻结协议的完整预算为每组100k，而本轮是事前规定的10k门控阶段；下一步必须先在本地CPU完成学习曲线、多seed稳定性、策略器×状态模式消融和validation指标统计，再决定是否从同一checkpoint续到100k。

## 启动与恢复协议

正式矩阵固定为`{Actor–Critic, PPO} × {explicit_only, latent_only, explicit_latent} × 3 seeds = 18`。每个run使用独立目录和日志；每次更新后原子写入策略、优化器、环境步数、validation gate、候选计数和运行统计。进程或服务器中断后从最近一次完整更新继续，不从头重跑。18-run启动器支持限并发、完整run跳过、失败run保留以及最终矩阵汇总。

机器可读门禁位于`代码/artifacts/preflight/pi_jwm_r6_online_gpu_readiness_v2/readiness.json`，人类可读报告位于同目录`report.md`。正式runner为`代码/scripts/run_r6_joint_policy_gpu_training.py`，矩阵启动器为`代码/scripts/launch_r6_gpu_training_matrix.py`。
