# PI-JWM v11 物理收益桥设计

日期：2026-07-19
状态：已确认，待实施

## 1. 问题与证据

上周的 AirFogSim 诊断已经建立任务收益、逐步 reward、RB/CPU 使用量、UAV 五类能耗和配对归因测量链，但本周正式 schema-v6 selector cache 中的 `task_utility` 与 `energy_total` 均为空数组。当前 selector 只使用 `predicted_energy_proxy` 等可观测代理，尚未从真实物理结果中学习候选动作的任务收益与能耗响应。

现有物理数据覆盖 seeds 0--4、15 个决策组和 66 个候选，其中只有 12 个决策时刻能与 60-seed 数据集的 `input_end_time` 精确对齐，且只有 7/15 个决策组存在非零 task-utility spread。该数据可用于 smoke 和接口验证，但不足以支持正式辅助模型。冻结的 3/10/20 步对照还表明，扩大 horizon 没有增加非平凡决策组，因此新增预算应优先用于扩大 seed 和有效决策点覆盖，而不是增加 rollout 长度。

## 2. 目标与非目标

本轮建立一个独立、可审计的 `PhysicalBenefitBridge`：从测试时可观测的状态、阶段和动作描述符预测候选相对默认动作的任务收益变化与 UAV 能耗变化，并输出校准后的不确定性区间。预测结果进入 selector 特征和 Pareto 安全回退；真实 AirFogSim future outcome 只用于 train/calibration 监督和冻结后的物理审计。

本轮不重新训练 PI-JWM world model，不把真实 future outcome 或 seed 身份加入测试特征，不使用固定能耗惩罚权重，不把 simulator candidate 与 selector candidate 宣称为一一相同动作，也不访问 matched test seeds 18--19 或 external holdout seeds 60--69。

## 3. 方案选择

采用“描述符级物理收益桥”，不采用以下两种方案：

- 不直接把旧 CSV 覆盖到 selector cache。旧数据量太小，且两套候选 ID 与动作语义不一致。
- 不立即训练端到端多任务 selector。物理标签仍是稀疏监督，直接联合训练会把候选可辨识性、物理响应和排序模型三个问题混在一起。

独立桥接层允许先验证物理收益是否能由测试时可观测量识别，再决定是否重新训练 selector，归因边界清楚。

## 4. 数据协议

### 4.1 Split 与时间对齐

- physical train：selector train seeds `0--15,20--43`；
- physical calibration：seeds `44--49`；
- selector validation：seeds `50--59`，只使用 bridge 预测和原 active-rate 标签完成模型选择；
- physical validation audit：bridge 与 selector 配置冻结后才可生成 seeds `50--59` 的真实物理结果；
- matched test 与 external holdout 保持锁定。

每个 seed 最多选 3 个有效决策点，每个决策点最多 8 个候选，固定 horizon `3`。物理 runner 必须从规范 `sample_index.csv` 中选择可精确匹配 `input_end_time` 的时刻，并在所有落盘表中写入 `sample_id`。无法精确对齐、动作未生效或缺少默认对照的行保留审计原因，但不进入监督集。

### 4.2 公共动作描述符

训练和推理两侧只通过公共描述符连接，不依赖候选名称硬映射：

- stage：offload、compute、return、unknown；
- normalized family：RB repair、offload--RB、compute--CPU、return-route、identity/control；
- 三步 RB/CPU total 与 count；
- offload 与 return 动作覆盖数；
- 修改 edge/task 数量和动作幅度；
- 当前任务、链路、资源和 PI-JWM forecast 上下文。

AirFogSim 的 `rb_count`、`mixed_offload_rb`、`cpu_scale`、`return_route` 分别归一到对应公共动作族。无法证明语义兼容的 `offload_target` 和其他候选只保留在物理审计中，不伪造 selector 级标签。

### 4.3 配对标签

每个物理候选都与相同 seed、sample_id、decision_time 的默认动作配对，保存：

- `delta_task_utility`；
- `delta_energy_total`；
- `delta_throughput`；
- UAV fly、hover、sensing、receive、send 五类能耗变化；
- `action_applied`、alignment 与 mapping provenance。

模型主监督只使用前两个配对目标，原始分项始终保留用于解释和质量审计。

## 5. Bridge 模型与校准

新增 `代码/src/pi_jwm/v11_physical_benefit.py`，提供以下稳定接口：

- `PhysicalBenefitTrainingBatch`：公共可观测特征、两个配对目标、seed/group provenance；
- `PhysicalBenefitPrediction`：task/energy mean、scale、LCB、UCB；
- `build_physical_training_batch()`；
- `fit_physical_benefit_bridge()`；
- `predict_physical_benefit()`；
- `augment_candidate_batch_with_physical_benefit()`；
- `audit_physical_bridge_protocol()`。

使用固定五折 seed-group crossfit 的小型树模型 ensemble，分别拟合 task delta 与 energy delta，不进行大规模超参搜索。OOF 预测用于与 stage-family median 基线比较；calibration seeds 只用于 split-conformal 区间缩放，不参与模型参数拟合。所有 fold、特征、模型和校准系数写入 manifest。

增强后的 `CandidateBatch` 追加 task/energy mean、scale、LCB、UCB 八个预测字段。原始 `CandidateOutcome.task_utility` 与 `energy_total` 不会被预测值冒充，仍保持“实际 outcome”语义。

## 6. Pareto 规则

selector 继续以 active-rate regret 为主排序目标，但只能从 bridge 允许的候选中选择。候选使用保守坐标：任务轴取 `task_lcb`，能耗轴取 `energy_ucb`。若另一个可用候选任务 LCB 不低、能耗 UCB 不高且至少一项严格更优，则当前候选被支配并移除；默认动作固定为坐标 `(0,0)`。

因此“任务收益下界为负且能耗增量上界为正”的候选会被默认动作支配。若所有非默认候选被支配、bridge 不可用或区间过宽，则 defer 到 ranked-allocation baseline。真实 AirFogSim task/energy outcome 不参与 validation/test 推理。

## 7. 质量门与停止条件

进入 selector 重训前，bridge 必须同时满足：

- train/calibration seed 无交叉，matched/external 访问数为 0；
- 监督行 100% 精确 sample-time 对齐、存在默认配对且动作确实生效；
- 公共描述符映射覆盖所有拟用于 selector 的动作族；
- task 与 energy 的 OOF MAE 均优于 stage-family median 基线；
- calibration 的两个 90% 区间经验覆盖率均不低于 80%；
- 特征泄漏审计中不出现 actual、future、oracle、outcome、seed 字段；
- 同 seed 和固定 fold 重跑结果一致。

任一门槛失败时，产物标记为 `diagnostic_only / physical_bridge_not_identifiable`，停止 selector 重训。通过后才允许重新打开 GPU，使用同一 schema-v6 rollout 标签加 bridge 预测特征重训 selector；validation 冻结门槛仍保持 RMSE `<230.8556` 且改善至少 `7/10` seeds，不因物理桥存在而放宽。
