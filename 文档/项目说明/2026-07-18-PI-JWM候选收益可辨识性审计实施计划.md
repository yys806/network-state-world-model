# PI-JWM v11 候选收益可辨识性审计实施计划

> 对应设计：`文档/项目说明/2026-07-18-PI-JWM候选收益可辨识性审计设计.md`  
> 执行原则：测试先行、本地 CPU 优先、锁定 split 不访问、每个阶段保留可重算证据

## 目标

复用冻结 schema-v5 train/calibration/validation actual-rollout 缓存，建立可解释的三层审计：sample opportunity、candidate benefit sign、candidate conditional ranking。先用简单模型证明测试时可见特征是否具有跨 seed 可辨识性，再决定是否值得启动下一轮 GPU selector。

本计划不修改 PI-JWM world model、不生成新标签、不访问 matched seeds `18--19` 或 external seeds `60--69`。

## 技术路线

- 数据：`CandidateBatch`、`CandidateOutcome` 和 schema-v5 manifest。
- 模型：scikit-learn Logistic/Ridge、Random Forest、HistGradientBoosting；本地已安装 XGBoost，作为固定可选对照。
- 验证：train 拟合，calibration 选择固定阈值，validation 只做冻结配置评价。
- 分组：训练内部以 seed 为 group，不做随机行级拆分。
- 结果：所有汇总均由 validation prediction trace 重算。

## Task 3：实现固定简单模型与 group-aware 评估

**文件：**

- 修改：`代码/src/pi_jwm/v11_benefit_identifiability.py`
- 修改：`代码/tests/test_v11_benefit_identifiability.py`

**步骤：**

1. 先写失败测试：group fold 的 train/validation seeds 不能交叉；同一 seed 的行必须留在同一侧。
2. 固定模型族和随机种子 `20260718`：
   - `linear`：LogisticRegression + Ridge；
   - `rf`：160 trees、`max_depth=16`、`min_samples_leaf=16`、`max_features=sqrt`；
   - `hgb`：200 iterations、learning rate `0.05`、31 leaves、`min_samples_leaf=40`；
   - `xgb`：300 trees、depth 6、learning rate `0.05`、row/column subsample `0.8`。
3. 每个模型族拟合：
   - opportunity classifier；
   - candidate sign classifier；
   - candidate benefit regressor。
4. 对单类别 fold 提供显式 constant-prior fallback，并在状态中记录；不能让 sklearn 异常导致静默跳过 seed。
5. 固定 calibration 阈值网格：opportunity/sign probability 各 `{0.50,0.65,0.80,0.90}`。候选必须同时满足：
   - opportunity probability 过门；
   - sign probability 过门；
   - predicted benefit `>0`；
   - candidate legal；
   否则选择 ranked-allocation baseline。
6. calibration 先排除不满足 precision `>=65%` 或 negative-selection rate `<=20%` 的阈值，再按 RMSE、defer ratio 依次选择；若没有可行阈值，固定为全 defer 并记录 `no_safe_threshold`。
7. 实现指标：ROC/PR-AUC、Brier、precision、negative-selection rate、sample 内 Spearman、top-1 positive ratio/regret、active-rate RMSE、link RMSE、activity F1、逐 seed 改善数。
8. 测试所有总量可由 prediction trace 重算，且空类/全同候选返回明确 `not_identifiable`，不制造 NaN 排名胜者。
9. 运行：

   ```powershell
   cd D:\shen\网络组\代码
   python -m unittest tests.test_v11_benefit_identifiability
   ```

**步骤：**

1. 使用完整 train/calibration/validation、全部固定特征组和模型族运行正式审计。
2. 若 RF/XGB 的完整候选行内存超过本机安全范围，只允许分批预测或使用 float32；不得减少 seed、候选、validation 或指标。任何模型因资源失败必须单独标记，其他固定模型继续完成。
3. 根据固定顺序选择最简单的过门模型：`linear -> hgb -> rf -> xgb`。只有前者未过门时才允许选择更复杂模型。
4. 验收门：
   - validation RMSE `<230.8556`；
   - 至少 7/10 seeds 改善；
   - executed positive precision `>=65%`；
   - negative-selection rate `<=20%`；
   - activity F1 drop `<=0.002`；
   - link RMSE degradation `<=2%`。
5. 输出结论分类：`identifiable`、`locally_identifiable` 或 `not_identifiable`。
6. 禁止在看过 validation 后增加新特征组合或修改阈值网格；若失败，按设计进入新的 schema-v6 设计回合。
