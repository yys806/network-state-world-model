# PI-JWM 时序可执行候选协议设计

日期：2026-07-19  
状态：已确认，实施中

## 1. 问题与目标

现有 selector-timed 物理标签在 rollout step 0 保持默认动作，并在 step 1/2 执行候选。旧候选保存 decision-time 的绝对 task-ID 映射；共享 step 0 后任务阶段和 ID 支持发生变化，81 个非默认候选中只有 3 个仍有效，且均无物理差异。该问题是候选动作语义失配，不是数据量或模型容量问题。

本轮目标是把候选改为“决策时冻结参数、执行时按当前合法动作集合解析”的因果策略规则。规则执行可以读取该步部署时同样可见的状态，但禁止读取 reward、能耗结果、任务完成结果、oracle 排名或其他 counterfactual 分支。完成后以 5-seed smoke 判断是否允许生成正式标签和启动 GPU selector 训练。

## 2. 方案比较

1. **稳定实体的完全开环动作**：绑定 node/edge 而非 task ID。泄漏边界最简单，但 AirFogSim 的通信、计算和回传接口最终仍以动态任务为单位，难以覆盖全部动作族。
2. **因果闭环策略规则（采用）**：候选冻结 family、scale、coverage、rank/mode 和时间模式；步骤 1/2 只将固定规则投影到当前合法任务。能覆盖 RB、offload、CPU、return-route，且与部署时反馈策略一致。
3. **把干预提前到 step 0**：最容易获得有效动作，但破坏已冻结的 PI-JWM selector 时间语义，旧结果也无法同口径比较，因此不采用。

## 3. 协议

每个新候选包含 `action_protocol=causal_policy_v1`，并保存以下可观测参数：

- `action_family`：`rb_count`、`offload_target`、`mixed_offload_rb`、`cpu_scale`、`return_route` 或 `default`；
- `rb_scale` / `cpu_scale`：相对当前默认分配的固定倍率；
- `policy_coverage`：最多作用的当前合法动作数；
- `policy_rank`：固定的替代邻居或路线排名；
- `return_route_mode`：`nearest_rsu` 或 `uav_relay`；
- `intervention_start_step` 与 `temporal_pattern`。

候选不得保存 formal runner 需要重新执行的 task-ID override。旧 task-ID 候选仍由 `precomputed_task_v0` 路径读取，仅用于历史复现。

执行顺序为：先采集当前合法动作集合，冻结本步解析结果；再执行默认 scheduler；最后覆盖该候选允许修改的动作并执行环境一步。解析阶段只使用当前状态和候选固定参数，不读取本步或未来 outcome。

## 4. 审计语义

每个候选、每一步分别记录：

- `action_applicable`：该规则在该步存在合法支持；
- `action_changed`：解析后的动作相对默认动作确实改变；
- 各动作族的 resolved/applied count；
- 固定策略参数、step、seed、sample_id 和 decision_time。

正式监督只接受所有激活步骤均合法的候选；物理差异覆盖率使用 `action_changed` 和配对 outcome 单独统计，不能把“合法但与默认相同”伪装成有效收益标签。

## 5. 质量门与产物

5-seed smoke 固定 seeds 0--4、每 seed 最多 3 个精确对齐决策点、每点最多 8 个候选、horizon 3。进入正式标签生成前要求：

- emitted 非默认候选的激活步骤 `action_applicable=100%`；
- 至少 70% 决策组包含有效非默认候选；
- 有效候选产生非零 task、throughput、resource 或 energy 配对差异；
- step-0 一致性、确定性、reward 重建和能耗守恒均无错误；
- matched test 18--19 与 external holdout 60--69 的访问计数仍为零。

产物写入 `代码/artifacts/reports/pi_jwm_v11_temporal_candidate_protocol_20260719/`，包含原始 CSV、质量门 JSON、复现命令、核心图、PPT 结论底稿和 SHA-256 清单。质量门失败时仍生成可汇报的根因、方法和证据，但禁止 GPU 训练。

## 6. 测试

测试覆盖固定规则校验、无 task-ID formal payload、RB 容量投影、CPU 非负倍率、offload/return 固定 rank、步骤 0 不干预、步骤 1/2 时序模式、applicable/changed 区分、同 seed 确定性和旧协议兼容性。开发阶段运行针对性测试；smoke 通过或失败冻结后再运行完整 tests/scripts 套件。
